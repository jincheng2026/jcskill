# 会话类型判断逻辑

识别当前会话属于哪种类型，以适配启动包的输出侧重。

## 判断流程

1. 扫描对话中的工具调用和内容关键词
2. 按下表匹配，命中最多信号的为主类型
3. 如果两种类型信号数量相近（差距 ≤1），判定为混合型

## 类型定义

### 编码/技术型

**识别信号**（命中 ≥2 即判定）：
- 使用了 Read/Edit/Write/Bash 工具操作代码文件
- 讨论了 bug、报错、调试、部署
- 涉及 git 操作（commit、branch、PR）
- 出现了代码片段或技术术语

**输出侧重**：
- 文件变更清单（必须完整，每个文件标注操作类型和状态）
- 技术决策和架构选择（为什么选这个方案）
- 报错记录和解决方式
- 未完成的技术任务要标注具体的下一步操作

### 备课/教学设计型

**识别信号**（命中 ≥2 即判定）：
- 提到课程、教案、学员、课件、行动手册
- 讨论教学目标、知识点、作业设计
- 涉及课程表、备课、上课
- 引用知识库或教学素材

**输出侧重**：
- 教学目标（这节课解决什么问题）
- 已确定的内容框架和大纲
- 素材来源（从哪找的、哪些已用、哪些待用）
- 学员画像相关的约束

### 内容创作型

**识别信号**（命中 ≥2 即判定）：
- 讨论选题、标题、文风、文稿
- 写推文、文章、视频脚本、口播稿
- 涉及发布平台（X、公众号、视频号）
- 引用素材库或文风 DNA

**输出侧重**：
- 选题定位（写什么、给谁看、在哪发）
- 文风约束（已确认的风格要求）
- 已有的素材和灵感
- 当前稿件状态（初稿/修改中/待定稿）

### 方案/策略型

**识别信号**（命中 ≥2 即判定）：
- 讨论方向选择、策略制定、方案对比
- 用到了利弊分析、决策矩阵
- 涉及商业决策、定价、合作模式
- 多轮讨论同一个问题的不同角度

**输出侧重**：
- 决策树（讨论了哪些选项、各自优劣）
- 用户的明确倾向和犹豫点
- 已排除的方向和原因
- 下一步需要的信息或行动

### 混合型

**判定条件**：两种以上类型的信号数量相近。

**处理方式**：
- 标注主类型和次类型：「混合型（主：编码 + 次：方案）」
- 按主类型的侧重输出，次类型的关键信息作为补充
- 如果无法区分主次，按信号出现的时间顺序排列
