# 六层提取规则

逐层扫描当前对话，按以下规则提取信息。

## 任务层（必需）

提取会话的**目标**，不是过程。

判断方法：
- 用户第一条消息通常包含任务目标
- 如果有多个任务，提取主线任务
- 用动词+名词概括：「调试 API 鉴权」「备第 5 节课」「写推文」

输出格式：一句话，≤30 字。

**提取不到 → 中止交接。**

## 状态层（必需）

提取进度快照：什么完成了、什么没完成、卡在哪。

判断方法：
- 扫描已生成的文件、已确认的方案、已解决的问题 → ✅
- 扫描讨论中但未落地的、提到要做但没做的 → 🔲
- 扫描明确说「卡住了」「还没想好」「等 XX」的 → ⛔

输出格式：
```
- ✅ [已完成事项]
- 🔲 [未完成事项，附原因]
```

**提取不到 → 中止交接。**

## 决策层（可选）

提取**已确认的决策**和决策理由。

识别信号：
- 用户说「就这样」「确定了」「用这个方案」
- AI 提出方案，用户没反对且后续基于此继续工作
- 明确的 A vs B 选择，且已选定

不算决策：
- 还在讨论中的选项
- AI 单方面建议但用户未确认的

输出格式：`[决策]：[原因]`

**提取不到 → 跳过此节，不显示。**

## 否决层（可选）

提取**试过但明确否掉的方案**和否决原因。

识别信号：
- 用户说「不行」「这个不好」「换一种」
- 尝试后报错/失败，确认放弃
- 明确对比后选了另一个

不算否决：
- 只是没采用但没讨论过的方案
- AI 提了但用户没回应的建议

输出格式：`❌ [方案]：[失败原因/否决原因]`

**提取不到 → 跳过此节，不显示。**

## 文件层（可选）

提取本次会话**实际操作过的文件路径**。

判断方法：
- Read/Edit/Write 工具操作过的文件
- Bash 命令中涉及的文件
- 明确讨论过内容的文件

每个文件标注：
- 操作类型：新建 / 修改 / 读取
- 当前状态：一句话说明

输出格式：`` `path/to/file` — [操作类型] [当前状态] ``

**提取不到 → 跳过此节，不显示。**

## 意图层（可选）

推断用户**没明确说出口的偏好、约束、风格要求**。

推断来源：
- 用户多次强调的关键词（如反复说「要真实」→ 不接受编造）
- 用户否决方案时透露的偏好（否掉花哨方案 → 偏好简洁）
- 用户的修改方向（反复缩短 → 偏好精简）
- 用户的工作习惯（一个一个来 → 不喜欢一次铺太大）

输出格式：`[偏好/约束] — 推断依据：[具体对话行为]`

**必须标注「推断」**，加提示：「以上偏好是我从对话中推断的，如有偏差请纠正」

**推断不到 → 跳过此节，不硬凑。**
