# JC 视频发布配文与简介生成器

## 核心定义

先判断用户要的到底是哪种文本，不要把所有「视频简介」都写成内容预告：

- **短视频发布配文／作者按语**：写在视频旁边的一条公开表达。默认用于抖音、小红书、视频号等短视频场景。
- **长视频简介／Show notes**：帮助观众理解长视频主题、章节、资料与观看路径。只有用户明确需要长视频简介、章节说明或详细内容地图时使用。
- **营销发布文案**：负责转化、活动宣传或行动号召。只有用户明确要求营销、引流、售卖或 CTA 时使用。

短视频场景默认生成「发布配文／作者按语」，不要默认写成长视频预告。

它不是「把逐字稿压缩一遍」，也不是「重新用一套钩子推销视频」。它应像作者本人刚经历、观察或想到一件事后，写给同路人的一则公开思考。

一句话定位：

> 作者把一个真实触发点、一个明确判断和少量具体信息，讲给已经刷到这条视频、对主题有基础兴趣的人。

## 内容组件分工

不要让发布配文重复承担其他组件的职责：

| 组件 | 主要任务 |
| --- | --- |
| 封面 | 制造冲突，让人停下来 |
| 视频开头 | 延续冲突，留住观众 |
| 视频正文 | 完整展开经历、论证与答案 |
| 发布配文 | 交代发帖缘由、放稳核心观点、补充真实语境 |
| 标签 | 归类、检索、强化主题 |

标题负责抓停，配文负责把观点放稳、把作者立住。

## 引流信息硬边界

- 短视频发布配文和视频简介中，禁止写入任何引流、领取或转化信息，包括「完整资料／提示词／设置步骤已整理到知识库」「评论区回复关键词」「私信领取」「主页获取」「加微信」以及点赞、关注、收藏等 CTA。
- 即使逐字稿、参考样本或已有文案中包含这些信息，也必须从简介中删除，不得自动沿用。
- 用户明确要求引流或转化时，应将任务判断为单独的「营销发布文案」，不能把 CTA 混入普通视频简介或发布配文。

## 这一步人要判断什么

| 环节 | 人判断什么 | AI 怎么做 |
| --- | --- | --- |
| 交付后 | 最终发哪一版、要不要再改 | AI 默认只给一版最强成稿；用户要多版才给，每版说明侧重点，由用户挑 |
| 标签 | 标签是否合适、要不要加平台活动话题 | AI 给 3～5 个准确标签，用户的运营要求（固定话题、活动标签）以用户说的为准 |
| 引流和转化 | 这条要不要带引流 | 默认不带；只有用户明确要求才按「营销发布文案」另写 |

AI 不替用户决定发布，交付成稿后停下。

## 先对口气

写之前，先看用户自己的东西，让配文听起来像用户本人，而不是像 AI。

用户的东西在「工作文件夹」里（和创作工作台 jincheng-workbench 用的是同一个）。按顺序找，找到就停：

1. 这个对话打开的文件夹，或者它往上几层，里面有 `内容草稿/` 或 `选题库/00_选题总览.md`。
2. 装了创作工作台：`~/Library/Application Support/jincheng-workbench/config.json` 里的 `workFolder`（`~` 开头的换成家目录）。
3. `~/Documents/jincheng-workbench/` 存在。

找到以后读这几处，有哪处读哪处：

- `写稿方法/08_我的口气样本.md`：用户发出去的同类稿、亲手改过的句子（改前 → 改后）。
- `已发布/` 下最近几条同平台作品的 `内容.md`，里面记的发布配文或简介。
- 这条内容自己的 `内容草稿/T001_选题名/定稿.md`：用户没贴逐字稿时，用它当逐字稿。

从这些材料里只学说话关系、句子长短、常用说法、怎么收尾、标签习惯，不照抄原句。用户的材料和下面「默认说话关系」冲突时，以用户材料为准。

都没有（找不到工作文件夹，或这几处都是空的）：不用建文件夹，开工时告诉用户一次「口气样本还是空的，这次按基本做法来」，然后按本 Skill 的默认说话关系写完。

## 输入模式

先使用当前对话里的全部材料。信息够就直接做，不重复询问。

- **逐字稿或完整文案**：提炼真实触发点、中心判断和具体锚点。
- **已有配文或简介**：先找出最影响效果的 1～3 个问题，再给出优化稿。
- **参考样本**：先拆解受众关系、功能与表达机制，再迁移可复用规律，不照抄措辞。
- **只有主题或要点**：基于已有信息生成，不补写未经提供的经历、数据、来源和结论。
- **平台、字数、语气、标签要求**：优先遵守用户的明确限制。

## 默认说话关系

短视频发布配文默认采用以下关系：

- 对象是已经刷到视频、对主题有基础兴趣的人，不是等待被教育的抽象「目标用户」。
- 作者是观察者、实践者和公开思考者，不是视频导览员，也不装全知专家。
- 作者与观众平视交流。优先说「我看到、我试过、我想到」，少用「你有没有发现」「你一直做错了」诊断观众。
- 专业感来自真实在场、具体实践、信息筛选和判断能力，不来自堆术语或自称权威。

如果用户提供了明确的人设、受众或参考样本，以用户材料为准。

## 工作流程

### 1. 确定文本类型与阅读阶段

先回答：

1. 这是短视频发布配文、长视频简介，还是营销文案？
2. 读者是在刷到视频、观看中、观看后，还是准备购买或报名？
3. 封面和视频开头已经完成了什么，配文还需要补什么？

短视频默认处于第二触点：读者已被封面、画面或开头初步吸引，配文负责确认题眼、补充语境和建立可信度，不负责重新拉一次冷流量。

### 2. 提取内容骨架

从材料中提取：

1. **中心命题**：这条内容最终只在说哪一件事？
2. **真实触发点**：最近看见、经历、尝试、收到或想到什么，促使作者做这条视频？
3. **作者判断**：作者现在怎么看？哪些是事实、体感、推测或阶段性结论？
4. **具体锚点**：有哪些动作、场景、数字、人物、产品、原话或框架可以证明这不是空谈？
5. **作者语言**：原稿中有哪些有辨识度的概念、比喻、狠话和自然口语？
6. **收束落点**：读完配文后，观众应该带走哪一个判断？

不要为了完整而平均概括逐字稿。只选择最能证明中心命题的内容。

### 3. 有参考样本时先做风格校准

用户要求拆解参考风格时，从必要维度分析，不急着生成：

- 在对谁说话；
- 处于观看链路的哪个阶段；
- 负责什么、不负责什么；
- 作者与观众是什么关系；
- 作者以什么身份出现；
- 开头如何定题；
- 真实感和可信度从哪里来；
- 中心命题、结构、句法、长度和信息密度；
- 第一人称、专业词、情绪、确定性和口语感；
- 悬念、结论、结尾与标签如何处理；
- 样本内部有哪些内容类型；
- 哪些规律可迁移，哪些只是该作者的资源、人设、口头禅或偶然疏漏。

把「优质样本的共同规律」「参考作者的个人习惯」「适合当前作者的最终标准」分开，避免机械模仿。

用户只要求直接生成时，在内部完成校准，不展示分析过程。

### 4. 选择内容结构

根据内容本身选择一种结构，不强迫所有配文套同一模板：

- **观察判断型**：判断 → 近期出现的 1～3 个信号 → 这意味着什么。
- **个人实践型**：最近做了什么 → 遇到什么具体矛盾 → 形成什么新认识。
- **现场／报告型**：在哪里看到什么 → 资料、人物或数据 → 得到什么判断。
- **问题探索型**：真实问题 → 情境或类比 → 框架 → 阶段性结论。
- **社区回应型**：谁说了什么 → 为什么想回应 → 当前反思或答案。
- **方法复盘型**：完成了什么 → 为什么复盘 → 必要步骤或要点。

列表只在内容天然存在步骤或并列要点时使用，不为了整齐强行列三点。

### 5. 组织短视频发布配文

默认只保留：

1. 1 个中心判断；
2. 1 个真实触发点；
3. 1～3 个具体锚点；
4. 1 句自然收束；
5. 3～5 个准确标签。

正文通常写成 1 个紧凑自然段，约 80～180 字。清单、报告或用户明确要求时可以更长；长度是结果，不是填充任务。

首句应尽快出现主题词、真实触发点或明确判断。可以直接亮结论，不必故意藏答案。悬念应来自「为什么这样判断」，而不是信息遮蔽。

已有封面或标题时，让配文补充「为什么此刻谈、判断从哪里来」，不要换一种说法重复封面。

### 6. 校准表达

- 优先使用第一人称交代真实经历、实践和判断来源。
- 使用整理过的口语：自然、完整、可朗读，不保留无意义口头禅。
- 使用具体名词、动作、场景和数字，少用空泛形容词。
- 允许中长句自然推进一层意思，不做短句轰炸。
- 给出判断，但用「我有一个感觉」「有没有一种可能」「大概」「目前看」区分体感、假设和事实。
- 让专业感来自结构、证据与判断，不靠堆概念。
- 允许保留一个真实的人类细节，但不要为了模仿强塞「哈哈」、表情或口头禅。
- 收束时优先复用原材料中已经成立的判断，不为了「高级感」另造抽象金句或擅自升华。
- 直接谈事情本身，少用「这条视频会讲清楚」「我也会分享」等元话语。

### 7. 守住事实边界

- 不虚构视频里没有的经历、方法、案例、数据、人物、来源和结论。
- 不把个人体感写成普遍事实，不把推测写成定论。
- 不把修辞升级成医学、科学或产品因果结论。
- 涉及研究、数字、产品功能和专业概念时，使用原材料能够支持的强度；无法核实就降低断言或省略。
- 标题可以更有冲突，配文应回到可验证的经历和判断。

### 8. 生成标签

默认使用 3～5 个真正相关的标签：

- 1 个领域词；
- 1～2 个具体议题词；
- 0～2 个场景、产品、人物或事件词。

不堆 `#干货分享`、`#效率提升`、`#必看` 等无法区分内容的泛标签，除非它们确实是用户的运营要求。

## 禁止写法

避免：

- 用「你有没有发现」机械识别受众痛点；
- 把观众描述成有缺陷、无知或一直做错；
- 用「真正、根本、必然、所有人」替代论证；
- 写「这条视频会讲清楚」「看完你将获得」等课程预告；
- 把整条逐字稿压成缩略版；
- 同时表达三四个中心；
- 为了点击隐藏本可直接给出的结论；
- 只有口号和情绪，没有真实触发点或具体锚点；
- 照抄参考作者的措辞、身份、资源和口头禅；
- 使用与作者不一致的营销腔；
- 在普通视频简介或发布配文中加入知识库领取、评论区回复、私信、主页、点赞、关注、收藏等引流或转化 CTA；
- 添加大量宽泛、无关或蹭热度的标签。

## 质量检查

交付前逐项检查：

1. 文本类型是否判断正确？
2. 前 30 个字能否看出主题、触发点或判断？
3. 整篇是否只服务一个中心命题？
4. 是否至少有一个真实场景、动作、来源、数字或具体名词？
5. 作者是在与同路人分享，还是在向抽象「目标用户」推销？
6. 「我」是否绑定真实经历，而不是自我包装？
7. 哪些是事实、体感和推测，边界是否清楚？
8. 是否补充了封面，而不是换句话重复封面？
9. 是否删掉了「这条视频会……」等无价值元话语？
10. 是否没有复述完整逐字稿？
11. 这段话能否原封不动用于任何同类账号？如果可以，说明太泛。
12. 强烈措辞是否有证据支撑？
13. 产品、研究、数字和医学词汇是否需要核实或降级表达？
14. 删除任意一句后若信息没有损失，那句是否应该删掉？
15. 标签是否少而准确？
16. 是否已经删除知识库领取、评论区回复关键词、私信、主页等全部引流信息？

任一关键项不满足，继续修改，不交付半成品。

## 输出格式

用户只要成稿时，默认只给一版最强、可直接复制发布的结果，不主动展示分析过程：

```markdown
<发布配文或简介正文>

#标签1 #标签2 #标签3
```

用户要求优化已有文案时，先简要列出最影响效果的 1～3 个问题，再给出成稿。

用户要求详细拆解参考样本时，输出：

1. 核心判断；
2. 在对谁说话；
3. 承担什么功能、不承担什么功能；
4. 必要维度的风格拆解；
5. 样本内部的结构类型；
6. 可迁移与不可机械复制的边界；
7. 可执行的写作规格和验收问题。

用户说「多说无益」「直接给我成稿」时，只输出最终配文与标签。只有用户明确要求多个版本时，才提供备选版本，并说明每版侧重点。
