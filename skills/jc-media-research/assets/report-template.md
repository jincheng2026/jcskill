# 媒体研究报告

按本次任务使用本模板。搜索数量、筛选漏斗、粉丝分布、合格与排除样本等章节仅适用于内容搜索和筛选；账号、视频和评论任务按下文「图表」中的对应要求交付。共同保留结论、研究范围、证据索引及限制，不为填写未涉及的章节自动新增任务；本次确需的证据和图表仍须完整。

## 结论

用三句话说明：实际发现了什么、证据有多强、最重要的限制是什么。不要用问句要求用户确认或选择下一步。

首屏紧接 4 个数据卡：搜索返回、去重后、合格样本、排除样本；再写请求次数、最高或实际费用和是否降过门槛。

## 筛选漏斗

用梯形或多边形分层展示原始结果、去重、直接相关、粉丝合格和点赞合格五步数量，并标明每一步减少多少、保留率是多少。0 条结果也保留完整漏斗和 0 值层。

## 数据分布图

在 HTML 正文直接嵌入粉丝数—点赞数散点图。横轴是采集时粉丝数，纵轴是采集时点赞数；区分合格和排除样本，标出粉丝上下限与点赞下限。只画 normalized 中两个字段都存在的记录，数据不足时显示真实可用点数和缺失原因。

同时嵌入粉丝体量分层梯形图，按 100–20,000、20,001–100,000、100,001–1,000,000、1,000,001 以上显示真实记录数，并单列粉丝字段缺失数量。

排除样本存在时，再嵌入排除原因水平条形图；每根条的长度和数字来自 `summary.exclusion_counts`。没有排除原因时保留图位并写明 0 条，不画假条。

## 合格样本

按最近 90 天优先展示卡片，逐条给出内容、作者、粉丝、点赞、收藏、分享、评论、发布时间、相关性理由、来源链接和证据 ID。不够目标数量时直接写实际数量；不显示与时效排序冲突的虚假名次。

## 排除样本

先总结主要排除原因，再展示最接近门槛的样本；完整明细默认折叠。按粉丝异常、账号过大、点赞不足、相邻主题、无关和证据缺失分组，保留逐条排除原因。

## 视频和账号证据

按 `[原始事实]`、`[程序计算]`、`[分析推断]`、`[用户确认]`、`[待验证]` 分开写。视频结构附时间段；重复模式至少连接两条独立视频。

## 评论发现

写清总行数、噪声、未分类、统计分母、各类行数和比例。代表评论附原视频链接、时间和点赞数。

## 图表

内容搜索和筛选的 HTML 主报告固定包含筛选漏斗、粉丝数—点赞数散点图、粉丝体量分层梯形图和排除原因条形图，默认由模板中的内联 ECharts 渲染，不要求模型徒手绘制内嵌 SVG；账号、视频和评论任务采用下列对应图表。独立导出的图表仍同时提供 SVG、明细 CSV 和 manifest。对应图表缺字段时显示失败原因和实际可用数量，不用装饰图代替。

账号、视频和评论任务也必须使用 HTML 主报告：账号报告至少给作品类型表现、时间分布和明确标为推断的商业路径图；视频报告在逐字稿通过验证后给结构时间轴和口播—画面—证据对应图；评论报告给主分类和需求分布，并写清分母。每份报告最多保留 3～6 张真正改变判断的图。

## 可做选题

每个选题写：真实证据、为什么适合当前用户、需要补的本人材料、不能照搬的部分。

## 可选的后续动作

当前任务已经完整交付后，最多列 3 个可以继续做的动作。使用陈述句，不把它们写成当前报告尚未完成，也不要求用户回复。

## 证据索引

列出证据 ID、来源、采集时间、支持的结论和状态。

## 输出要求

默认输出自包含 HTML 主报告和同名 `_preview.png`，使用内联 CSS，以及从 `assets/page-template.html` 起步、构建时全文内联的 `assets/vendor/echarts.min.js`；不依赖 CDN、外部字体或运行时网络请求。仅在模板路径不可用时按主入口使用旧版兜底，原有渲染自查和预览验证仍须完成。桌面和手机都能正常阅读，图表不得造成横向滚动，限制信息必须直接可见。Markdown 可以作为证据伴随文件，但不能代替 HTML 主报告。聊天交付时先展示 PNG 预览，再给 HTML 路径。
