# 报告、图表、费用和公开安全

## 报告顺序

1. 先写最重要的判断。
2. 写研究范围、实际样本和限制。
3. 给合格样本与排除样本。
4. 展示视频、账号和评论证据。
5. 区分事实、计算、推断、用户确认和待验证。
6. 把可选的后续动作放在完整结果之后，不用问句要求用户继续。

不要把「今天」「全平台」「最强」「用户都需要」等超出样本范围的词写进结论。

## 默认可视化报告

内容搜索、账号研究、视频拆解和评论研究都必须生成自包含、可离线打开、手机可读的 HTML 主报告。内容搜索和筛选任务以 `assets/page-template.html` 和构建时内联的 ECharts 为默认入口，从 normalized JSON 生成 `reports/research_report.html`；`scripts/render_report.py` 默认读取该模板并内联随包 ECharts，仍须完成质量检查。以下清单适用于内容搜索和筛选报告；账号、视频和评论报告采用下文「不同任务的最小图表」，共同保留首屏结论、证据、研究范围和限制。内容搜索和筛选报告至少包含：

- 首屏一句结论和 4 个关键数据卡。
- 从原始结果到最终合格样本的梯形筛选漏斗。
- 粉丝数—点赞数散点图，区分合格与排除样本，并标出硬门槛。
- 粉丝体量分层梯形图，显示低粉门槛内、2 万～10 万、10 万～100 万、100 万以上的真实数量。
- 排除原因水平条形图，直接显示各原因的真实数量。
- 按时效优先展示的合格样本卡片及来源链接。
- 排除原因总结和可展开明细。
- 研究范围、费用、数据时间和限制。

找到 0 条时也必须生成 HTML，首屏直说「没有找到符合当前硬门槛的样本」，并保留 4 个图位的真实空状态。某张图缺少可用字段时，保留图框并写清「可用数据点为 0」或缺少的字段；不得补造样本、只留下 Markdown 长表，或以「请选择下一步」结束。

## 不同任务的最小图表

- 内容搜索：筛选漏斗、粉丝数—点赞数散点图、粉丝分层梯形图、排除原因条形图。
- 账号研究：按发布时间排序的作品表现、相对账号自身基线图和逐条基线明细。有类型标签时再附分类型表现；商业路径仅在有证据时作带引用的推断说明，不画成已发生转化。
- 视频拆解：按原文段落展示结构、演化操作分布和来源覆盖。有 `precise_timing` 时才增加精确时间轴；没有时间轴但有已复核原文时仍可作文字结构分析。
- 评论研究：顶层主分类、回复覆盖；提炼问题时另加问题回答情况分布。标注总行数、噪声、层级未知、未分类和统计分母。

每份报告保留 3～6 张真正帮助判断的图。不要为了好看重复同一组数字，也不要把漏斗、梯形、散点或进度条当装饰。

## 预览和聊天交付

HTML 生成后运行 `scripts/render_report_preview.py`，生成同名 `_preview.png`。预览至少覆盖首屏结论、关键数据和主要图表；PNG 必须通过文件头、尺寸和最小文件大小校验。

最终回复的顺序固定为：

1. 一句话结论。
2. 直接展示 PNG 预览，让用户不用离开聊天就能看到图。
3. 给 HTML 主报告路径；需要时再给 Markdown、CSV、SVG 和证据索引。

不能只给 HTML 路径。预览失败时保留 HTML，并明确报告中有哪些图、失败原因和一个处理动作。

## HTML 内嵌图表合同

关键词和内容筛选报告固定提供 4 个图位，不由执行模型临时决定要不要画：

1. `selection-funnel`：使用 `summary.funnel`，以真实梯形或多边形分层呈现阶段名称、数量和保留率。阶段数量为 0 时保留该层。
2. `followers-likes-scatter`：只使用同时存在 `follower_count` 和 `like_count` 的 normalized 记录。区分合格与排除样本，标出粉丝上下限和点赞下限；使用线性轴或对数轴都必须明确标注。
3. `follower-tiers`：只使用存在 `follower_count` 的 normalized 记录，按 100–20,000、20,001–100,000、100,001–1,000,000、1,000,001 以上分层画梯形；同时显示未进入分层的缺失值数量。
4. `exclusion-reasons`：只使用 `summary.exclusion_counts` 画水平条形图。没有排除原因时显示 0 数据状态，不制造条形。

四个图位以及所有数据图表统一使用内联 ECharts 渲染：从 `assets/page-template.html` 复制起步，构建时把 `assets/vendor/echarts.min.js` 全文内联进 HTML，保持自包含、可离线打开、无 CDN、无外部字体、无任何网络请求。禁止徒手计算 SVG/HTML 坐标绘制数据图（LLM 手算坐标必然产生重叠与截断，2026-08-16 定案）；点阵图行标签必须走 graphic 通道加固定左栏，不得用隐藏散点冒充标签。图名、坐标轴或阶段、图例和样本口径必须直接可见；不能用装饰圆点、随机宽度或与数据无关的几何形状冒充图表。

## 渲染自查（交付前必过）

每份 HTML 主报告生成后运行 `scripts/qa_page.py 报告.html`：脚本自动截图亮暗两版，机械检查页面截断、大段空白尾、横向溢出，任一命中即不许交付；PASS 后必须逐张查看输出的分区截图，确认无文字重叠、图形完整、风格与模板一致，再进入聊天交付。分区截图路径随交付一并给出，作为自查证据。

## 独立图表规则

只画能帮助判断的图。完整研究通常不超过 6 张：

- 搜索筛选漏斗。
- 合格样本的粉丝数与点赞数分布。
- 发布时间与表现变化。
- 账号内容分组与表现。
- 评论主分类分布。
- 证据完整度。

每张图必须同时有：

- SVG。
- 对应明细 CSV。
- manifest 中的图名、输入文件、筛选条件、字段、分母、来源和采集时间。

不同平台指标不画在同一比较轴。数据不足、字段缺失或独立图表失败时，在 HTML 中回退为清楚的卡片或表格并说明原因。

## 费用计划

付费前生成机器可读计划，至少包括：

```text
平台
端点和方法
每种请求的数量
实时价格来源和查询时间
预计最高费用
默认样本上限
停止条件
计划哈希
```

授权记录必须匹配计划哈希。任务累计不超过 120 次请求且预计不超过 1.00 美元时，守卫脚本生成任务级自动授权；这不是用户手动批准，不能伪造成用户输入。超出上限才要求用户提供与计划匹配的明确批准。请求参数、游标或数量变化后重新生成计划并重新计算累计预算。账本记录请求指纹、时间、状态、缓存命中和已知费用；不得记录用户提示词、搜索关键词、响应正文、凭据或完整授权头。

超时后扣费状态不明时，把请求标为 `unknown_charge_state` 并停止。只有用户确认或通过服务端证据解决状态后才能继续。

## 本地数据和公开交付分开

- `raw/`：保存原始证据，只留在任务工作区。
- `normalized/`：只保留字段合同允许的内容。
- `reports/`：只引用规范化数据和必要证据。
- 公开包：只包含 Skill 源文件、合成测试数据和公开模板。

公开分享不得包含：

- API 凭据、访问令牌、授权头或 Cookie。
- 临时媒体签名和设备追踪参数。
- 个人账号标识、手机号、位置和私密资料。
- 真实评论、原始平台响应、用户逐字稿和用户画像。
- 本机绝对路径、模型文件、依赖目录、缓存和日志。

采用两道门：先用字段白名单生成 normalized，再递归扫描文本、JSON、CSV、Markdown、URL 和压缩包清单。任何命中都让打包失败，不能只给警告后继续。

## 报告完成检查

按当前任务检查适用项；未做评论统计、视频结构分析或付费请求时，不为补齐相关条目自动新增这些工作。当前任务实际依赖的证据、费用和报告质量检查不得跳过。

- 所有样本都能回到来源。
- 采集时间来自对应响应，不是统一猜测。
- 筛选参数、去重键、排除原因和排序方法已保存。
- 评论百分比可由逐行数据复算。
- 视频结构有字幕或逐字稿。
- `reports/research_report.html` 已生成并能离线打开；0 条结果也有完整报告。
- 当前任务的 HTML 主报告已有同名 `_preview.png`，最终回复会直接展示它。
- 内容搜索和筛选报告已读回确认存在 `selection-funnel`、`followers-likes-scatter`、`follower-tiers` 和 `exclusion-reasons` 四个图位；账号、视频和评论报告已核对各自必需图表。图中元素来自对应 normalized 字段、summary 或已验证的任务证据。
- 独立图表如存在，均有明细和 manifest。
- 费用数字有计划或账本证据。
- 公开输出通过隐私扫描。
- 普通成功路径没有要求用户追加确认；只有缺少关键输入、费用超限或真实执行失败才追问。

## v2 报告和运行入口

render_report.py 支持 content_research、account_research、video_research、comment_research、question_research。默认读取 assets/page-template.html 的页面框架并内联 ECharts，图表数据位于页面 chart-data JSON，图形来自同一份规范化明细。来源链接经过白名单和脱敏，真实任务的原始响应不会整体进入 HTML。

新增分析先运行 research_decisions.py validate-analysis，来源校验通过后，把 sources 与 analysis 放进报告输入。报告中的每项演化判断展开即可核对原文。问题研究输入直接采用 questions 命令产物，保留实际覆盖和回答状态。

qa_page.py 接受 --browser 或 CHROME_PATH，并支持 --mobile。截图机械检查只检查有限的截断、空白与边缘迹象；仍需用实际浏览器检查横向溢出、图表就绪状态和逐屏视觉效果。reportReady 不证明研究判断正确。

公开包仅对 assets/vendor/echarts.min.js、assets/vendor/LICENSE.echarts.txt、assets/vendor/NOTICE.echarts.txt 作精确白名单，不开放整个 vendor 目录。保留 ECharts 5.5.1 上游许可证和 NOTICE；不打包其他依赖缓存。打包脚本对解压副本再次核查本地引用与依赖，整体验收再执行离线渲染。

## 凭据初始化

macOS 尚无凭据时，让用户在自己的终端执行下面命令，-w 放最后；终端密码提示处输入 TikHub Key，不是 Mac 登录密码。不要让用户在聊天里发送 Key。

    security add-generic-password -a tikhub -s tikhub-api -U -w

再次运行 credential-status，只报告 configured。非 macOS 可使用本机环境变量 TIKHUB_API_KEY、TIKHUB_TOKEN 或 TIKHUB_BEARER_TOKEN，不写入命令参数、资料和报告。

命令行 Chrome 截图的窄屏检查使用 500px，避免部分版本把 500px 布局裁成 390px 图片。实际手机请在浏览器 viewport 设为 390px，检查 documentElement.scrollWidth 不大于 innerWidth 并目检。命令行截图超时会结束本次独立浏览器进程；只有实际 PNG 与图表就绪标记都取得，才接受该截图。
