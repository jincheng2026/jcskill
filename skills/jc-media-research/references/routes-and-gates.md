# 任务路由和停止点

## 先选最小任务

| 用户输入 | 默认任务 | 本轮完整交付 | 交付后的用户判断 |
| --- | --- | --- | --- |
| 内容方向、关键词 | 搜索与选题 | 合格样本、排除原因、限制和 HTML 报告 | 采用、修改或放弃哪个选题 |
| 单条视频链接或媒体 | 视频拆解 | 字幕来源、分段逐字稿和单次观察 | 哪些结构值得借鉴 |
| 创作者账号 | 账号研究 | 实际读取范围、作品与评论证据、重复模式和报告 | 哪些模式与自己有关 |
| 要写个人口播 | 共同写稿 | 有材料时给完整稿；有非关键缺口时给带 `[待补]` 的草稿 | 观点、经历、数字和最终稿 |
| 多条原稿、想看演化 | 语义段落对照 | 对齐、差异、原文引用、采用建议 | 采用哪种逻辑与表达 |
| 评论、未解决问题 | 评论需求研究 | 层级与覆盖、问题原话、回答状态、内容机会 | 哪个切入点适合自己 |
| 高表现作品、普通作品 | 对照研究 | 选样理由、六维差异、证据、其他解释与测试建议 | 先测试哪个变化 |
| 已有 CSV、JSON、报告 | 离线分析 | 数据质量检查、可复算结论和报告 | 是否采用结论 |

不要因为用户给了一个关键词，就自动完成下载、评论、转写和写稿。只有用户明确说「做完整研究」，才串联多条任务。

## 开始前在后台检查

按顺序检查：

1. 研究对象和平台是否明确。
2. 输出是候选、视频拆解、账号报告，还是个人口播。
3. 是否已有能直接使用的数据、定位、经历和素材；选题推荐前就读取。
4. 是否会调用付费接口。
5. 输出目录是否是新的独立目录。

能够从用户消息和现有材料确定的事情直接执行，不把检查清单发给用户。只有命中以下三个原因时才能追问，而且一次只问一个能解除阻塞的问题：

- `required_input_missing`：缺少不可替代的关键输入。
- `cost_limit_exceeded`：任务累计将超过 120 次付费请求或 1.00 美元。
- `execution_failed`：真实执行失败，必须由用户采取动作。

合格结果少于目标数量，包括 0 条，不属于追问原因；应直接交付真实结果和原因。

## 后台自动完成与例外

| 阶段 | 默认动作 | 只有什么情况才问用户 |
| --- | --- | --- | --- |
| 搜索范围 | 根据明确任务自动扩展直接相关关键词，保存计划后执行 | 平台或主题确实无法确定 |
| 费用 | 120 次且 1.00 美元以内绑定计划哈希自动授权 | 累计请求数或费用将超限 |
| 候选 | 自动完成筛选；完整研究自动选择最多 3 条并写明依据 | 不因结果少或需要选样本而追问 |
| 结论 | 区分事实、计算、推断和待验证，直接生成报告 | 真实失败导致证据无法取得 |
| 写稿 | 先用现有本人材料，缺口用 `[待补]` | 缺少核心输入会导致必然编造 |
| 定稿 | 交付后按用户反馈修改，用户说「确定」后固定原文 | 不在交付前强制确认结构 |

## 必须停止

出现以下任一情况，停止相应步骤并说明原因：

- 来源路径不清楚，可能写错项目。
- 输出文件已存在，可能覆盖旧证据。
- 付费计划超过任务级自动授权上限，或请求数、价格变化后将超限。
- 鉴权失败，或超时后无法判断是否已经扣费。
- 视频不可读取、字幕来源不可靠、转写不完整。
- 评论没有原视频链接，或统计无法回到逐行标签。
- 图表没有对应明细或分母。
- 写稿缺少不可替代的核心经历或观点，继续会必然编造。
- 公开包扫描发现凭据、临时签名链接、个人账号数据、真实任务材料或本机路径。

停止一个步骤不等于停止整个任务。仍可继续完成不受影响的离线整理、字段检查、报告骨架和待确认清单。

## 状态用词

- 「候选」：AI 已筛出的可用结果，用户可以在完整交付后采用、修改或放弃；它不是强制停顿点。
- 「已确认」：用户明确选择，固定原文或范围。
- 「待验证」：缺少证据，不能写成事实。
- 「已完成」：当前任务的证据、计算和输出验证已过关；不以用户再回复一次作为完成条件。
