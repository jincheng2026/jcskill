# PRD: daily-planning Skill

> 版本：v1（基于 2026-04-29 实测对话迭代）
> 用户：锦成（个人自用）
> 输出位置：`~/LLM-Wiki/planning/YYYY-MM-DD.md`

---

## 1. 背景与目标

### 问题
锦成事情多、节奏快，缺一个稳定的"日规划入口"：
- 临场决定做什么 → 容易被紧急但不重要的事拉走
- 想到的事散在微信/录音/对话/脑子里 → 没有沉淀
- 规划做了执行不了 → 缺 If-Then 预案
- 周一立的 flag 周三就忘 → 没有跨天延续机制

### 目标
做一个**每日 5-10 分钟、产出可执行日计划**的 Skill。

### 不做（Non-Goals）
- 周规划、月规划、长期目标管理（另起 Skill）
- 自动同步日历 / 自动提醒
- AI 主动塞事项（违反核心规则）
- 跨天数据分析

---

## 2. 核心规则（最高优先级）

> 这五条任何时候不能违反。

1. **以锦成当下输入为主**——可以从 TELOS 翻事项作为补充，但不擅自塞
2. **昨日/历史未完成项逐条问「留/砍/挪」**——不自动延续
3. **WOOP 化**——每个 P0 必须有 If-Then 预案（障碍 → 预案）
4. **54% 心法**——标注 1-2 件"今日大事"
5. **主动砍事**——每天明确放弃几件并写清理由

---

## 3. 实测发现（v1 迭代纪要）

> 2026-04-29 测试跑通，沉淀以下经验，写进 v1 流程：

1. **"今日大事"允许 1-2 件，不强制 1 件**——锦成实测选了 BD 都列，纯 1 件太严格
2. **P0 追问障碍时若答"无法解决" → 自动降级搁置区**（不再当 P0 督促）
3. **障碍问诊要给具体选项启发**——只问"障碍是什么"太空，要给「文案没想好 / 单纯不想动手 / 完美主义拖延 / 别的」这种候选项让用户对号入座。鼓励诚实描述**心理障碍**（"单纯不想动手""完美主义"），不只是技术障碍
4. **讨论阶段 vs 写入阶段两套形式**：
   - 讨论：详细完整，AI 给判断+理由，用户拍板（信息密度高）
   - 写入：D2 极简（callout + 全角空格对齐），克制无装饰
5. **P0 事项中途会升级/降级**——如"张机预告消息"中途升级为"发完整对接流程"，要支持
6. **候选清单全量呈现**——AI 整理候选清单后，主动让用户确认"没漏什么信息吧"，AI 自查后坦诚汇报漏项
7. **输入源可以是对话/录音/纪要**——不局限于"今天有哪些事要做"这种空白提问

## 4. 用户场景

### A. 早上开工（主场景）
锦成说"帮我做今天的日规划" / "/日规划" → Skill 走完整流程

### B. 基于上文对话延续（次主场景）
对话里刚梳理过纪要/录音 → 锦成说"基于上面内容做今天的规划"
→ Skill 直接从上下文提取候选清单，不再问"有哪些事"

### C. 临时插入
中午有新事项 → 锦成说"今天加一件 XXX"
→ Skill 读今天文件，追加并 WOOP 化

### D. 晚上回看（暂不做，留给 daily-review）

## 5. 完整工作流（v1）

```
触发
  ↓
① 检查最近一份日规划文件 (LLM-Wiki/planning/)
   - 有未完成项 → 逐条问「留/砍/挪」
   - 没有 → 跳过
  ↓
② 收集今日事项
   方式 A：从上下文（对话/录音/纪要）提取候选清单
   方式 B：直接问"今天要做什么"
   方式 C：锦成主动说"参考一下我本月目标"→ 读 TELOS goals.md/projects.md
  ↓
③ 候选清单全量呈现 + 让锦成确认"没漏什么信息吗"
   - AI 主动自查上下文里有没有漏的事
   - 锦成补充/确认
  ↓
④ AI 给优先级判断（P0/P1/砍）+ 写明每条理由
   - 不只是分级，要给"为什么是 P0"的逻辑（死线？复利？阻塞？）
   - 锦成可调整
  ↓
⑤ 提取「今日大事」（1-2 件）
   - AI 从 P0 里挑候选 + 给倾向 + 说理由（如"单点死线 vs 长线复利"）
   - 锦成拍板：选 1 / 选 2 / 都列
  ↓
⑥ WOOP 化所有 P0
   - 对每个 P0 问："最可能的障碍是什么？"
   - 给具体候选项启发（文案问题 / 执行问题 / 心理障碍 / 别的）
   - 鼓励诚实描述心理障碍（完美主义 / 不想动 / 怕尴尬）
   - 如答"无法解决" → 降级搁置区
   - 否则生成 If-Then 预案（具体到时间点+动作）
  ↓
⑦ 砍事
   - 默认 P2 候选 + 锦成补充
   - 每条写明砍的理由（"不是死线/本周内做就行/对方不等"）
  ↓
⑧ 写入 LLM-Wiki/planning/YYYY-MM-DD.md（D2 极简格式）
   - callout 突出今日大事
   - P0 用「障碍　→　预案」全角空格对齐
   - 保留"晚上回看"区块（手动填写）
```

## 6. 输出格式（D2 极简版）

```markdown
---
date: 2026-04-29
created: HH:MM
---

# 2026-04-29

> [!important] 今日大事
> ① [大事1] —— [一句话理由]
> ② [大事2] —— [一句话理由]

## P0

**① [事项]**（今日大事）
[障碍场景]　→　[If-Then 预案，含时间点+动作]

**② [事项]**（今日大事）
[障碍场景]　→　[If-Then 预案]

**③ [事项]**
[障碍场景]　→　[If-Then 预案]

---

**P1**　[事项] · [事项]

**砍**　[事项]（理由）· [事项]（理由）

**搁置**　[无法解决的事，附说明]

---

## 🌙 晚上回看（手动填写）
- 今日大事是否完成？
- P0 的 If-Then 是否触发？预案是否执行？
- 明日重点：
```

### 格式细节
- 用 Obsidian `[!important]` callout 突出今日大事
- 「障碍 → 预案」用全角空格 `　` 对齐，不用表格
- 不用 emoji 装饰（"🌙 晚上回看"是唯一例外，作为视觉锚点）
- P0 事项加粗 + 圆圈数字 ①②③
- 完全砍掉的事写"砍"区，无法解决的写"搁置"区，两者不混

## 9. 边界处理

| 场景 | 处理 |
|---|---|
| 历史规划不存在（首次） | 跳过未完成项追溯，进入 ② |
| 同一天重复触发 | 进入"追加模式"，读今天文件再加事 |
| 锦成只想列清单不想 WOOP | 口头说"快速版"，跳过 WOOP 化和大事提取 |
| TELOS 文件读不到 | 跳过 TELOS 整合 |
| P0 障碍答"无法解决" | 自动降级搁置区，不算 P0 |
| 锦成中途修改某件事的范围 | 接受变更，重新跑该事项的 WOOP |
| AI 整理候选清单时遗漏 | 锦成"没漏什么吧"提示后，AI 自查上下文坦诚汇报 |

- [ ] 5-10 分钟内能产出一份完整日规划
- [ ] 历史未完成项逐条询问，不自动延续

- [ ] 一定有「砍事」字段（哪怕写"今天没什么要砍"）

- [ ] 文件路径：`LLM-Wiki/planning/YYYY-MM-DD.md`
- [ ] 文件可在 Obsidian 直接打开，callout 正确渲染
- [ ] 讨论阶段不偷懒省略信息（保持完整问诊）

## 11. 反模式（NEVER）

> AI 容易掉进的坑，明确禁止：

- AI 主动从 TELOS 翻事项塞进今天（除非锦成说要参考）
- AI 自动把昨天未完成项搬到今天（必须逐条问）
- AI 给优先级却不给理由（必须说清"为什么是 P0/砍"）
- AI 给笼统的 If-Then（如"如果有障碍，就克服"）→ 必须具体到时间点+动作
- 讨论阶段过度浓缩问题（用户曾反馈"提问太抽象"）
- 写入文件时加多余装饰（emoji / 花线 / 表格）
- 整理候选清单时悄悄漏事项不告知

## 13. 设计哲学（来自 LLM-Wiki 老喻+万维钢的规划方法论）

> 这部分是 Skill 的"为什么"——给未来读 SKILL.md 的 LLM 解释为什么这么设计。

- **WOOP（万维钢18讲）**：日规划最大的痛点是"知道该做什么但临场做不出来"。If-Then 是给一天写"自动执行代码"——情境出现时不靠意志力靠预案
- **54% 心法（老喻052讲）**：日规划不追求 100% 完成，只要每天做对关键动作就赢。"今日大事"就是这个关键动作
- **被动决策（老喻070讲）**：好习惯靠系统不靠决心。日规划的输出是预案而不是 to-do 列表
- **选择性放弃（老喻103讲）**：周/日规划真正的难点是减事，不是加事。"砍事"区强制每天做减法
- **工程思维（老喻030讲）**：把模糊的"我要把 XX 做好"拆成"今天的下一步动作"

LLM 在执行流程时，遇到犹豫，回到这五条哲学判断怎么做。
