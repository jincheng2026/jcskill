# 轻量评审与反馈记录

## 原则

反馈先如实记录，不因为一条样本就自动升级成长期判断。AI 负责把反馈分成「给已有判断补一个例子、缩小已有判断的适用范围、只留作案例、暂不沉淀、新增判断」。写进判断库（工作文件夹的 `写稿方法/07_我的判断库.md`）的规矩：只有给已有判断补一个例子（加一行证据，不改判断和适用范围）AI 可以自己做并告诉用户；新增、改说法、改适用范围、处理冲突、删除，都要用户逐条同意，写进去之前先查重，把库里原文和候选并排摆出来。

不用评分表、自动阈值、事件编号、状态流转或规则自动升级。

保留用户原话，也允许 AI 根据同一条内容的原稿、改稿、终稿、以往重复出现的做法和发布数据，把修改原因继续想深。用户明确认可的理解写成「用户确认」；AI 根据多处上下文得出的理解写成「AI 归纳」，同时列出证据和适用范围，不冒充用户原话。只有两份已确认的信息互相冲突、又会改变当前交付时，才在写稿中途请用户裁决；AI 归纳要写进判断库时，按上面的规矩交用户同意。

## 发布前轻量评审

用户说「评审」「终审」「发布前检查」，或完整脚本、教程和发布素材已经齐备时，执行一次轻量评审。目标是拦截少数会伤害发布的问题，不重新改写整条内容。

### 五个评审门

1. **收获与开头**
   - 开头是否尽快让目标观众知道为什么值得继续看；不固定为前 5 秒，也不固定为问题、收益或结果句式；
   - 正片是否已经交付核心价值，而不是把答案全部藏进资料包。
2. **真实口播**
   - 同一角色是否只保留一个主要称呼；
   - 类比是否只负责第一次理解，后续案例和证据是否回到具体动作与数据；
   - 真实试读是否卡顿。没有真人试读证据时写「口播未实测」，不能写成已通过实测。
3. **事实与证据**
   - 外部数字、模型能力和产品设置是否使用最新的一手来源核对；社区讨论只用于发现风险，不代替官方或原始证据；
   - 区分「配置已创建」「模型可直接使用」「运行时确实委派到指定模型」，不得把前两者写成第三者；
   - 后台核查可以严格，口播只保留已成立的明确结论。必要边界放进教程，不把防御性免责声明塞进口播；
   - 证据包遵守最小必要原则，不主动增加账号额度、个人后台等隐私材料。
4. **教程与承诺交付**
   - 视频承诺的完整提示词、教程、文件或入口是否真实存在并可用；
   - 面向零基础观众的关键操作是否说清复制或输入什么、放到哪里、怎样执行，以及成功后会看到什么；
   - 一键提示词只承担核心配置和基础检查；兼容性研究、安全审计和运行时深验收单独处理，不塞进一分钟交付；
   - 教程是否先给资产，再承接交流入口，正文保持纯净。
5. **平台承接**
   - 是否已经按平台分别生成收尾、标题、简介和作者评论，而不是复制同一套引导动作；
   - 小红书视频、字幕、标题和简介不得要求观众「评论 XXX」。发布配文可以只陈述教程或 Skill 已整理好；发布后允许作者在评论区自然说明适用平台，并告知教程已放入粉丝群、大家自取；
   - 作者评论是主动提供教程去向，不得改写成「先评论关键词，再领取」。

### 评审结论

只允许三种结论：

- **通过：** 没有阻断项，只继续用户当前要求的发布内容，不自动生成整套分平台发布包；
- **修改后通过：** 列出最多 3 条必须修改项，修改并复查后交付；
- **暂缓发布：** 核心结果不成立、承诺资产不存在，或存在明确平台硬风险。说明唯一阻断原因和解除条件。

不输出分数、长表格或泛泛建议。不是必须修改的问题放进反馈记录，不在终审阶段扩写内容。

## 单条反馈格式

反馈记在工作文件夹的 `写稿方法/反馈记录.md`，每条一节：

```markdown
## YYYY-MM-DD｜T001 内容标题

- 阶段：叙事 / 脚本 / 拍摄 / 剪辑 / 成片 / 发布数据 / Skill
- 用户原话：
- 本次修改：
- AI 对修改原因的理解：注明「用户确认」或「AI 归纳」，后者列出依据
- 用户回应：认可 / 修正或补充 / 未单独裁决
- 最终反馈：用户已裁决时按裁决写；未单独裁决时保留用户原话与 AI 归纳的边界
- 采用证据：对话中已确认 / 已实际发布 / 外部状态未知
- 结果：待观察 / 有效 / 无效
- 关联内容：可选
```

用户反馈不够明确时也可以先记录，结果写「待观察」，不要替用户补造结论。聊天中没有明确确认，只能说明「未单独裁决」，不能据此推断现实中没有采用；若能核实内容已经发布，以实际发布版本作为采用证据。AI 归纳可以用于当前判断，但必须保留来源、适用范围和不确定性；单条样本不能单独升级成通用判断。

## 复盘判断

用户触发复盘或迭代时，检查：

1. 反馈是否清楚、具体、可执行；
2. 它指向真实问题、个人偏好，还是偶然结果；
3. 是否在不同内容中重复出现；
4. 是否与已有创作判断冲突；
5. 是否需要更多样本或发布数据；
6. 现在修改规则是否真的会提高内容质量。

复盘只输出三种结论之一：

- **暂不升级：** 证据不足或只是单次偏好；
- **候选观察：** 有价值，但需要更多样本；
- **更新判断：** 直接说明给哪条判断补证据、缩小范围、转为案例，或新增哪条判断。

没有写入授权时，只记录建议，不改判断库。用户明确要求「沉淀好」「整理进判断库」时，AI 按证据整理；给已有判断补例子可以直接写，新增、改说法、改适用范围、处理冲突、删除仍要用户逐条同意；只有证据冲突自己解决不了时才停下请用户判断。

## 用真实内容验证 Skill

Skill 修改后，默认直接用于用户今天及后续真实创作，不要求重做过去已经完成的视频。每条内容只记录：

- 写稿前分析是否帮助用户更快、更全面地想到关键细节；
- 第一版叙事框架保留了多少；
- 是否重复过去已经指出的问题；
- 是否发生推倒重写，或仍需用户大量亲自重写；
- 从开始讨论到逐字稿确认的实际耗时；
- 教程视频的文案与画面拆解是否真正帮助拍摄，还是增加了无效负担。

一条真实内容只能暴露明显问题，不能单独证明流程已经成熟。继续在后续真实内容中观察，再决定是否修改长期规则。
