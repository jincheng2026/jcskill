# 更新数据权威索引 Skill

## 触发方式
- `/updateSourceOfTruth`（唯一触发方式）

## 背景说明

`SOURCE_OF_TRUTH.md` 是一个项目级的「数据权威索引」文件，放在项目根目录。它解决一个核心问题：**当项目里有大量文件时，AI 和用户都不知道「某个信息到底在哪个文件里」「同一个数据有多个版本时以哪个为准」。**

这个文件包含三个部分：
1. **快速查找表**：「要找什么 → 去哪个文件」
2. **目录职责说明**：每个目录放什么、不放什么
3. **数据冲突声明**：同一数据多个版本时，以哪个为准

它不是 CLAUDE.md（行为规则），而是一张「地图」。CLAUDE.md 里需要有一条指引让 AI 知道去读这个文件。

## 执行逻辑

### 0. 前置检查

先检查项目根目录是否存在 `SOURCE_OF_TRUTH.md`。

**如果不存在**，说明用户是第一次使用，进入「初始化流程」：

1. 向用户解释这个文件的作用（用上面的背景说明）
2. 扫描项目根目录的文件夹结构（只看第一层和第二层）
3. 评估文件组织状态：
   - **如果文件结构清晰**（有明确的分类目录）→ 直接开始建立索引，逐个目录询问用户「这个目录是放什么的」「哪个文件是最重要的」
   - **如果文件结构混乱**（大量文件散落在根目录、没有分类）→ 先告诉用户「你的文件需要先整理一下，否则索引建了也没用」，建议先分类整理，再回来建索引
4. 根据用户回答，生成 `SOURCE_OF_TRUTH.md`
5. 检查 `CLAUDE.md` 是否有指向 `SOURCE_OF_TRUTH.md` 的引用，如果没有则建议用户添加

**如果已存在**，进入「更新流程」（下面的步骤 1-5）。

### 1. 判断更新类型

根据用户的输入，判断属于以下哪种情况：

**A. 用户明确指出要改什么**
- 例：「推文库的路径写错了」「陪跑数据应该以 XX 文件为准」
- → 直接读 `SOURCE_OF_TRUTH.md`，找到对应条目，修改

**B. 用户刚用完某个文件，想更新描述**
- 例：「刚才用的那个文件，帮我更新到索引里」
- → 回顾当前会话上下文，找到用户刚操作的文件，更新或新增到对应表格

**C. 用户没有具体指示，想做一次检查**
- 例：「检查一下索引」「索引还准吗」
- → 读 `SOURCE_OF_TRUTH.md`，逐个检查快速查找表中的文件路径是否存在（用 Glob 验证），报告失效的条目，让用户确认如何修改

### 2. 执行更新

1. 读取 `SOURCE_OF_TRUTH.md`
2. 定位需要修改的区域（快速查找 / 目录职责 / 数据冲突声明 / 归档标注）
3. 用 Edit 工具精确修改对应行
4. **不做全文重写**，只改需要改的部分

### 3. 更新规则

- **路径变更**：文件移动或重命名后，更新路径
- **描述修正**：用户说「这个文件不是干这个的」，修正备注
- **新增条目**：发现重要文件不在索引中，新增一行
- **删除条目**：文件已删除或合并，移除对应行
- **冲突更新**：用户确认了新的权威版本，更新数据冲突声明
- **归档标注**：文件过时了，移到「已标记为归档/过时的目录」

### 4. 输出格式

每次更新后，简要输出修改内容：

```
✅ SOURCE_OF_TRUTH.md 已更新：
- [修改] 快速查找 → 推文原文：路径从 `旧路径` 改为 `新路径`
- [新增] 快速查找 → 引流款数据：`02-业务运营/商业模式分析/引流款月度数据_....md`
- [删除] 数据冲突 → Q4 总收入：已确认为 xxx 万
```

### 5. 不做的事

- 不重新扫描全部文件（那是初次建立索引时做的事）
- 不自作主张修改用户没提到的内容
- 不修改 CLAUDE.md（那是规则文件，不是索引）
