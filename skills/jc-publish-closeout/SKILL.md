# 发布后建档和抓数据

视频发出去以后，这个 Skill 做三件事：给这条视频建一个档案，认出它在各平台上的作品，到发布后 12 小时和 7 天各抓一次数据。7 天数据齐了，交给 jc-media-review 写复盘。

所有命令都用本 Skill 文件夹里的脚本 `<本 Skill 目录>/scripts/stats.py`（下面简写成 `stats.py`）。运行前先确定本 SKILL.md 所在的文件夹，用完整路径调用，不依赖当前所在的文件夹。脚本只用 Python 自带的模块，不用装东西。每个命令加 `-h` 能看全部参数。

## 先找到工作文件夹

你的选题、草稿、素材都放在「工作文件夹」里（和创作工作台 jincheng-workbench 用的是同一个）。每次开工先找到它，按顺序找，找到就停：

1. 这个对话打开的文件夹，或者它往上几层，里面有 `内容草稿/` 或 `选题库/00_选题总览.md`。
2. 装了创作工作台：`~/Library/Application Support/jincheng-workbench/config.json` 里的 `workFolder`（`~` 开头的换成家目录）。
3. `~/Documents/jincheng-workbench/` 存在。

都没有：用总入口 `jc` 的建文件夹脚本建好（和本 Skill 装在同一个地方，`<本 Skill 目录>/../jc/scripts/init_workfolder.py`，运行 `python3 <这个路径>`，它只补缺的、不覆盖），告诉用户一句建在哪。找不到 `jc` 时，只在 `~/Documents/jincheng-workbench/` 下建 `已发布/` 和 `选题库/`。

本 Skill 读写这几处：`已发布/`（档案、`00_已发布总览.md`、`我的账号.md`），`选题库/00_选题总览.md` 和选题卡，`内容草稿/T001_选题名/`（只读，找定稿、简介、封面文字）。

## 这些地方停下等你

AI 能做的都由 AI 做，下面几件事要你来判断，AI 做到这一步就停下问，你答了再接着做：

| 什么时候 | 你要判断什么 |
| --- | --- |
| 本机有好几个像是这条视频的成片或封面，分不清 | 哪个是真正发出去的那个。AI 把候选和区别一次列清，只问一次 |
| 在你主页里找作品，拿不准是哪一条 | 是候选里的哪一条，或者都不是。AI 宁可不认，也不认错 |
| 逐字稿里有拿不准的字，成片画面上也看不清 | 原话是什么 |
| 要抓小红书的数据，或者这次花钱超过默认上限 | 同不同意花这笔钱（小红书每次 0.01 美元，抖音每次约 0.001 美元） |
| 第一次用、AI 工具能建定时任务时 | 要不要让它到点自动抓 |
| 第一次用 | 贴一次你各平台的主页链接，以后认作品就不用再贴作品链接 |

## 第一次用

1. **TikHub 密钥**：抓数据靠 TikHub（一个按次收费的社媒数据接口）。先运行 `python3 stats.py check`，它只说读没读到密钥、余额多少，不扣钱。没读到时，照它打印的话告诉用户怎么办：去 https://user.tikhub.io 注册，在 API Key 页面创建一个（权限建议全选），充值（最低 5 美元，按次扣费）；装了创作工作台的，在它「市场调研」页的「数据来源」里粘贴；没装的，**请用户自己在「终端」里**运行 `security add-generic-password -a tikhub -s tikhub-api -U -w`，在提示处粘贴密钥、回车。不让用户把密钥发进聊天，AI 也不读、不打印密钥。不想用 TikHub 也能用：数据请用户从平台后台截图或报数，AI 手动记，写明来源。
2. **你的主页链接**：请用户贴一次抖音、小红书的主页链接（浏览器地址栏里的那个），存下来：

   ```bash
   python3 stats.py account --workfolder <工作文件夹> --platform 抖音 --url <主页链接>
   ```

   存在 `已发布/我的账号.md`。以后发了新视频，AI 到这些主页的最近作品里找，不用用户再贴作品链接。视频号 TikHub 拉不到，不用存。

## 流程

### 第 1 步：确认是哪条视频

用户说「我发了」，AI 先自己把这条视频的发布事实凑齐，**不让用户填作品编号、作品 ID**：

- **T 编号和标题**：看 `选题库/00_选题总览.md` 里状态是「草稿」的、`内容草稿/` 里最近改过的文件夹，和用户说的标题对上。
- **简介、封面文字**：`内容草稿/T001_选题名/` 里的定稿、创作页定下的标题和简介，或者 jc-jianjie 写的配文；以发出去的为准。
- **成片、封面**：草稿文件夹、剪辑软件的导出文件夹、「下载」里最近的视频和图片。按标题、时长、修改时间认；只有一个明显对得上的就用它。
- **发布时间**：用户说的时间；没说就问一句「几点发的」。

好几个候选分不清，或者几样东西对不上，把所有拿不准的地方合在一起，只问一次。

### 第 2 步：校正版逐字稿

档案里只放**对成片转写后校正过的逐字稿**，不拿录制前写的稿子代替（录的时候常会临场改）。

1. 用 jc-zhuanxie 转写成片，按它的校正标准改掉识别错误。
2. 拿不准的字，看成片画面上烧录的字幕：按逐字稿的时间点抽一帧看，例如 `ffmpeg -ss 00:00:12.5 -i 成片.mp4 -frames:v 1 字幕帧.png`。字幕是剪辑时定下的文字，比两遍识别都准；字幕为了避免平台限流改了写法的（比如把某个平台名写成谐音），逐字稿跟字幕走。
3. 还拿不准的，问用户。
4. 原始识别、分段转写、抽的帧都是中间文件，放在系统临时文件夹，不进档案。

找不到成片时，先建档，逐字稿那一节留着；找到成片再补。

### 第 3 步：建档

```bash
python3 stats.py create --workfolder <工作文件夹> --title "发出去的标题" --published "2026-10-07 20:00" \
  --id T001 --intro "简介" --cover-text "封面文字" --cover <封面图> --video <成片> --duration 52.4 \
  --transcript <校正版逐字稿.txt> [--platforms 抖音,小红书,视频号]
```

它会：

- 建 `已发布/2026-10-07-标题/`，里面 `内容.md`、`数据.jsonl`，封面**复制**进来（原件不动）；成片不复制，只记路径。
- 更新 `已发布/00_已发布总览.md`（一条视频一行，最新的在最上面）。
- 有 T 编号时，把 `选题库/00_选题总览.md` 里这一行的「状态」改成「已发布」、「发布日期」空着就填上，选题卡挪到同一类的 `已做/`。只改那一行的两格，不动表格别的地方。
- 重复调用不重复建：同一个 T 编号，或者同标题同一天的档案已经有了，就沿用它，只补空着的项；和档案里不一样的项不改，打印出来让用户决定。

`--platforms` 是打算发的平台，先都记成「预计发布」。**预计发布不等于已经发布**，只有真找到作品才改成「已找到」。

### 第 4 步：认出各平台的作品

- **用户贴了作品链接**：最省事。

  ```bash
  python3 stats.py link --archive <档案> --url <作品链接>
  ```

  不写 `--published` 时，它从平台读发布时间和时长（抖音每次约 0.001 美元，在默认上限内直接跑；小红书要先问用户）。
- **没贴链接，存过主页**：

  ```bash
  python3 stats.py find --archive <档案> --platform 抖音 --apply
  ```

  它拉你主页最近 20 条作品，按标题、发布时间、时长三样打分。一条明显最像才认定并记进档案；拿不准就列出最多 3 个候选，AI 拿给用户问一次是哪条（都不是也行），用户挑好用 `link --url` 记；一条都不像就说没找到，可能还在审核，过几个小时再找，或者请用户贴链接。
- **视频号**：TikHub 拉不到。问用户视频号发了没有、几点发的，用 `link --platform 视频号 --published "2026-10-07 20:05"` 记下（有链接就加 `--url`）。
- **不发的平台**：`link --platform 小红书 --status 不发`。

每个平台记下作品以后，`内容.md` 的「数据」一节就会列出这个平台 12 小时、7 天两个到点时间（按这个平台自己的发布时间算）。

### 第 5 步：到点了怎么抓

- **AI 工具能建定时任务**（例如 Claude Code 桌面版的定时任务、Codex 的自动化）：问用户要不要到点自动抓。要的话，按「数据」一节里的到点时间各建一个一次性任务，任务内容写：「用 jc-publish-closeout 抓 <档案路径> 的 12 小时数据：运行 `python3 <stats.py 的完整路径> record --archive <档案路径> --point 12h`，把结果告诉我」。小红书每次都要用户同意，建任务前问一次，用户同意了就在命令里加 `--agreed-budget 0.02`。定时任务要能读到工作文件夹和钥匙串，只在本机运行的那种才行。
- **不支持，或者用户不要**：到点时间已经写在 `内容.md` 里。用户下次说「看看数据」「抓一下数据」，或者进总入口 jc 时，AI 先跑：

  ```bash
  python3 stats.py due --workfolder <工作文件夹>
  ```

  它列出到点还没抓的观察点、已经过了多久，还有发布 3 天内还没认出作品的平台、7 天数据齐了还没复盘的档案。没有要做的就一句话。

### 第 6 步：抓数

```bash
python3 stats.py record --archive <档案> --point 12h     # 或 --point 7d
```

- 不写 `--platform` 时，把认出了作品的平台挨个抓一遍。**一个平台失败不拖垮别的平台**：抓到的照写，没抓到的说原因，下次 `due` 还会提醒。
- 每次抓数在 `数据.jsonl` 追加一行原始记录（目标时间、实际采集时间、晚了多少分钟、来源、各项数），只追加，不改旧行；`内容.md` 的数据表和已发布总览跟着更新。
- **晚采照写**：实际采集时间比目标时间晚多少，表里写多少；12 小时点晚过 2 小时、7 天点晚过 12 小时的，标「偏晚」。不把晚采的数说成准点的数。还没到点的不抓，现在抓的数不能当那个时间点的数。
- 已经记过的观察点不重复记（真要补记加 `--again`，表里取最后一行）。
- 播放数：平台公开接口一般拿不到，表里写「—」，不当成 0。用户从后台看到了，可以手动补。
- **视频号和截图**：请用户从视频号助手（或各平台后台）截图、报数，手动记，写明来源：

  ```bash
  python3 stats.py record --archive <档案> --point 12h --platform 视频号 --likes 12 --collects 3 --comments 1 --shares 0 \
    --source 视频号助手截图 --collected-at "2026-10-08 08:40"
  ```

  `--collected-at` 写截图上的时间（或者用户看数的时间），不写就是现在。
- **实在采不到**（比如过了很久、作品删了）：`record --platform 抖音 --point 7d --missed "原因"`，以后不再提醒，表里写「没采到」和原因，不拿别的时间的数顶替。

7 天的数抓完，告诉用户这条可以复盘了（用 jc-media-review）。

### 想随时看一眼

- `python3 stats.py fetch <作品链接>`：抓一条作品现在的数，只打印、不写档案。
- `python3 stats.py comments <作品链接> --max 50`：抓公开评论原话（jc-media-review 复盘时用）。

## 花钱规矩

- 单次最多自动花 0.02 美元，当天累计最多自动花 0.20 美元；小红书接口、超过这两个上限、评论要超过 200 条，脚本会停下（退出码 3），打印要问用户的话。AI 把话转给用户，用户在对话里明确同意后，加 `--agreed-budget <金额>` 再跑。
- 出错的请求 TikHub 不扣钱；等回复超时的可能扣了，脚本不会自动重试，说清楚再让用户决定。
- 用量记在 `已发布/.tikhub/用量.jsonl`（只记时间、接口、花费，不记密钥）。

## 档案长什么样

一条视频一个文件夹 `已发布/YYYY-MM-DD-标题/`：

- `内容.md`：发布事实（T 编号、标题、简介、封面文字、发布时间、时长、封面、成片路径）、平台链接表、数据表、完整逐字稿（校正版）、复盘。「数据」一节由脚本生成，别手改；别的节可以直接改。
- `封面.png`（或别的格式）：复制来的封面。
- `数据.jsonl`：每次抓数一行。
- `.history/`：写复盘、换逐字稿之前自动备份的旧 `内容.md`。

`已发布/00_已发布总览.md` 一条视频一行：发布日期、标题、T 编号、各平台 7 天的点赞／收藏、复盘了没有、档案链接。最新的在最上面。它由脚本按各档案重新生成，别手改。写稿的 Skill 出标题前会读最近的几行，看哪类标题数据好。

各部分的格式见 [references/档案格式.md](references/档案格式.md)。

## 规矩

1. 不让用户填作品编号、作品 ID；能自己找的自己找，拿不准只问一次。
2. 不把「预计发布」写成「已发布」；只有真找到作品才写「已找到」。
3. 认作品看标题、发布时间、时长，拿不准宁可不认。
4. 逐字稿只放对成片转写后校正的版本，不拿录制前的稿子代替。
5. 每次抓数记目标时间、实际采集时间、晚了多久；不把晚采的数说成准点的数，不拿别的时间的数顶替。
6. 不编数据。拿不到的写「—」，没采到的写「没采到」和原因。
7. 一个平台失败不拖垮整条；重复调用不重复建档、不重复记数。
8. 原件只复制不移动；不删东西，要删的挪进工作文件夹的 `回收站/YYYY-MM-DD_原文件名`。
9. 发布以后不再改标题、简介、封面文字，只照实记。

## 出问题时

- `check` 说密钥不对、余额不够：照它的话告诉用户，别的平台和手动记数照常做。
- 解析不出 TikHub 的返回：脚本把原始返回存在 `已发布/.tikhub/原始返回/`（不含密钥），告诉用户这一个平台这次没抓到，其他照常。
- 选题总览里找不到这个 T 编号：档案照建，告诉用户选题状态没改，请他确认编号。
- `内容.md` 被手改得认不出「平台链接」表：不硬改，指给用户看是哪一节。

## 和别的 Skill 的分工

- 写稿、改稿：jc-jiaocheng-video。简介、配文：jc-jianjie。转写成片：jc-zhuanxie。
- 7 天数据齐了写复盘：jc-media-review（它读这里的档案，复盘写回同一个 `内容.md`）。
- 复盘得出的结论要变成下次写稿的规矩：jc-skill-writer。
