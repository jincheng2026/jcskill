# 档案格式

给要读写档案的 AI 看（jc-media-review、写稿时看往期数据的 Skill、总入口 jc）。能用 `stats.py` 的地方都用它改，别手改脚本负责的部分。

## 已发布/YYYY-MM-DD-标题/内容.md

各节用「## 」开头，顺序固定：

1. `## 发布事实`：每行 `- **项**：值`，项有 T 编号、标题、简介、封面文字、发布时间（`YYYY-MM-DD HH:MM`）、时长（`52.4 秒`）、封面（指向档案里封面图的 Markdown 链接）、成片（完整路径，后面注「没复制进档案」）。可以手改。
2. `## 平台链接`：一张表，表头 `平台 | 状态 | 链接 | 发布时间 | 时长 | 怎么认的`。状态只写：预计发布 / 已找到 / 没找到 / 不发。**各平台的发布时间只认这张表**，12 小时、7 天的到点时间都从这里算。用 `stats.py link` 改。
3. `## 数据`：两行注释标记中间那张表，由脚本按 `数据.jsonl` 生成，手改会被覆盖。表头 `平台 | 观察点 | 目标时间 | 实际采集时间 | 晚了多久 | 播放 | 点赞 | 收藏 | 评论 | 转发 | 来源`。没到点写「还没到」，到点没抓写「到点了，还没抓」，采不到写「没采到：原因」，拿不到的数写「—」。
4. `## 完整逐字稿（校正版）`：对成片转写、校正后的全文。可以手改。
5. `## 复盘`：没复盘时是「（还没复盘）」。用 `stats.py review` 写入，第一行是「> 复盘于 YYYY-MM-DD，用户看过、同意后写入。」，里面的小标题用 `####`。

## 已发布/YYYY-MM-DD-标题/数据.jsonl

一次抓数一行 JSON，只追加。字段：

| 字段 | 意思 |
| --- | --- |
| `platform` | 抖音 / 小红书 / 视频号 |
| `point` | `12h` 或 `7d` |
| `target_at` | 目标时间（这个平台的发布时间 + 12 小时或 7 天） |
| `collected_at` | 实际采集时间 |
| `delay`、`delay_minutes` | 晚了多久（人话）、晚了多少分钟 |
| `status` | `ok`（采到了）或 `missed`（采不到，`note` 写原因） |
| `source` | TikHub / 视频号助手截图 / 用户报数 …… |
| `plays`、`likes`、`collects`、`comments`、`shares` | 播放、点赞、收藏、评论、转发；拿不到是 `null`，不是 0 |
| `link`、`work_id`、`title` | 作品链接、平台上的作品编号、平台上的标题 |
| `recorded_at` | 写这一行的时间 |

同一个平台同一个观察点有好几行时，以最后一行为准。

## 已发布/00_已发布总览.md

一条视频一行，按发布日期从新到旧。表头：`发布日期 | 标题 | T 编号 | 抖音 7 天 点赞／收藏 | 小红书 7 天 点赞／收藏 | 视频号 7 天 点赞／收藏 | 复盘 | 档案`。点赞／收藏写成 `9000／2400`；没满 7 天写「未满 7 天」，没认出作品写「还没认出」，不发写「不发」。复盘一列写「还没复盘」或「已复盘 YYYY-MM-DD」。由 `stats.py overview`（建档、记数、写复盘时自动跑）重新生成。

## 已发布/我的账号.md

表头 `平台 | 主页链接`，用 `stats.py account` 写。`find` 到这些主页的最近作品里认作品。
