# 对标内容入库

把用户已经选中的社媒内容完整、可追溯地存进工作文件夹的对标素材库。只负责从「用户已经提供的材料」到 `市场调研/对标素材/` 的入库，不替用户判断这条值不值得对标。

下面的 `<本 Skill 目录>` 指这份 SKILL.md 所在的文件夹，运行脚本前先确定它的绝对路径；`<工作文件夹>` 见下一节。

## 先找到工作文件夹

你的选题、草稿、素材都放在「工作文件夹」里（和创作工作台 jincheng-workbench 用的是同一个）。每次开工先找到它，按顺序找，找到就停：

1. 这个对话打开的文件夹，或者它往上几层，里面有 `内容草稿/` 或 `选题库/00_选题总览.md`。
2. 装了创作工作台：`~/Library/Application Support/jincheng-workbench/config.json` 里的 `workFolder`（`~` 开头的换成家目录）。
3. `~/Documents/jincheng-workbench/` 存在。

都没有：用总入口 `jc` 的建文件夹脚本建好（和本 Skill 装在同一个地方，`<本 Skill 目录>/../jc/scripts/init_workfolder.py`，运行 `python3 <这个路径>`，它只补缺的、不覆盖），告诉用户一句建在哪。找不到 `jc` 时，只在 `~/Documents/jincheng-workbench/` 下建本 Skill 要用的 `市场调研/对标素材/未参考/` 和 `回收站/`。

本 Skill 只用到工作文件夹里的这几处：

| 放什么 | 位置 |
| --- | --- |
| 还没支撑过正式内容的对标素材（一条作品一个文件夹） | `市场调研/对标素材/未参考/<平台>/<平台>_<标题>_<作品ID>/` |
| 已经实际支撑过一条正式内容的对标素材（去重时也要扫） | `市场调研/对标素材/已参考/<平台>/` |
| 入库过程中的暂存 | `市场调研/对标素材/.staging/` |
| 每次入库的检查记录（只追加） | `市场调研/对标素材/_入库检查报告.md` |
| 验收后清掉的转写中间版本 | `回收站/YYYY-MM-DD_对标素材逐字稿中间版本/` |

## 开工条件

1. 至少取得以下两类信息之一：
   - 社媒助手或平台页面复制的作品信息，最好含平台、作品 ID、标题、正文或描述、分享链接；
   - 用户已经下载的图片或视频文件，并能从用户提供的信息确认来源作品。
2. 缺少平台、作品 ID 和可稳定识别的分享链接，导致无法去重时，只追问这一项。其他缺失字段写「未提供」，不阻塞保存已有的真实材料。
3. 有视频要转写时，确认 jc-zhuanxie 装在本 Skill 旁边（`<本 Skill 目录>/../jc-zhuanxie/scripts/transcribe_batch.py` 存在）。找不到就告诉用户先装本仓库的 jc-zhuanxie；没有它可以先存原文和媒体，但这条有视频的素材不算入库完成。

详细字段、命名和完成标准见 [入库规范](references/intake-contract.md)。

## 这一步人要判断什么

| 时候 | 人判断什么 | AI 怎么做 |
| --- | --- | --- |
| 开工前 | 哪条内容值得对标、要不要入库 | 只处理用户自己选中的内容；不替用户找、不评价值不值得 |
| 去重命中 | 是同一条吗、要不要往旧文件夹补资料 | 停下，报告已有的文件夹；用户说补才在原文件夹补，不新建第二份 |
| 只有标题相同 | 是不是同一条 | 不判重复，列出标题相同的文件夹请用户核对 |
| 输入信息和媒体对不上 | 哪份材料属于哪条作品 | 停在暂存区列出冲突，不猜 |
| 逐字稿里拿不准的词 | 到底是哪个词 | 保留 `【疑似：…】` 或 `【待确认】`，入库后报告里列出来 |

## 硬规则

1. 完整保存用户复制的原始内容，不概括、不改写、不分析；整理后的字段和原始复制内容分区保存。
2. 写入前按「平台＋作品 ID」「去掉时效参数后的分享链接」「已记录的媒体 SHA-256（文件指纹，内容一样指纹就一样）」三层去重。命中任一层时停止新建，报告现有目录；用户明确要求补资料时只补现有目录。只有标题相同不判重，提示用户人工核对。
3. 本地媒体只复制，不移动、不删除原文件；目标文件已存在时不覆盖。先写进 `.staging/` 暂存，验收通过后再改名为正式目录。
4. 视频必须先经 `file`、`ffprobe` 和短解码检查；文件存在不等于视频可用。
5. 视频没有完整逐字稿时，用 jc-zhuanxie 转写（火山引擎豆包语音，它自带本地备用引擎），不换别的转写工具。转写和验收阶段必须保留原始识别、分段复核、校正版和验收结果；校正版通过验收前不得清理中间证据。
6. 把校正版逐字稿完整并入 `笔记信息.md` 的「校正版逐字稿」部分，笔记只链接校正版文件和同名字幕。正式入库完成后，`转写/` 下只保留 `校正版逐字稿/`（校正版 `.md` 和同名时间码字幕 `.srt`）；原始识别、分段复核、分段源、manifest 和 validation 全部移进工作文件夹的回收站，不留在正式素材目录，也不清理还在 `.staging/` 或没通过验收的条目。
7. 有视频的素材必须带时间码字幕：校正版通过验收后、清理中间版本之前，用原始识别的时间给校正版生成同名 `.srt`（文字取校正版，时间取识别结果，不重新转写）。之后拆解参考视频时按时间找原句、写稿时从某一句开始看原片，都靠这份字幕；没有字幕的新视频素材不算入库完成。
8. 新素材只写入 `市场调研/对标素材/未参考/<平台>/` 和 `市场调研/对标素材/_入库检查报告.md`；不自动生成选题、不总结写法规律、不分析标题或结构。
9. 不保存 token、Cookie、带密钥的请求头或其他登录凭据。带时效签名的媒体 URL 只用于当次下载，不写入长期笔记。

## 入库流程

### 1. 读取并盘点输入

从用户消息和附件中列出：平台、作品 ID、标题、作者、发布时间、分享链接、正文或描述、可见数据、图片 URL、本地图片、本地视频、已有逐字稿。把「用户提供的事实」「从文件实际检测到的信息」「缺失信息」分开。

### 2. 去重并给出写入计划

递归扫描 `市场调研/对标素材/已参考/*/*/笔记信息.md` 与 `市场调研/对标素材/未参考/*/*/笔记信息.md`，执行三层去重。没有重复时确定：

- 正式目录：`市场调研/对标素材/未参考/<平台>/<平台>_<标题>_<作品ID或链接短哈希>/`
- 暂存目录：`市场调研/对标素材/.staging/<同名目录>/`
- 媒体命名：图片按原顺序为 `01.jpg`、`02.jpg`……；单个视频为 `视频.原扩展名`

标题只替换操作系统不允许的字符，不改原文。写入前运行：

```bash
python3 <本 Skill 目录>/scripts/validate_workspace.py "<工作文件夹>" --target "市场调研/对标素材/未参考/<平台>/准备写入的目录" --json
```

目标还没创建时，这一步用来确认路径和现有重复项；不要因此创建空的正式目录。

### 3. 写入暂存目录

创建 `笔记信息.md`，先写结构化字段，再原样写入「原始复制内容」。复制本地媒体；只有用户已经提供公开图片 URL 时才下载图片。不要自行登录平台、调用付费接口（逐字稿转写用的火山引擎接口除外）或扩大采集范围。

视频存在时记录：文件名、字节数、时长、编码检测结果和 SHA-256。没有封面图时，从可读视频第 1 秒截取 `01.jpg`，并在笔记中说明来源。

### 4. 补齐视频逐字稿

视频没有可靠逐字稿时，调用 jc-zhuanxie（第一次用时它会检查火山的 Key，缺 Key 怎么办照它的说明做）：

```bash
python3 <本 Skill 目录>/../jc-zhuanxie/scripts/transcribe_batch.py \
  "暂存目录" \
  "暂存目录/转写"
```

然后按 jc-zhuanxie 的流程写分段复核和校正版，跑它的 `validate_delivery.py`。完成后读取 `转写/validation.json`。只有验收通过的校正版才能并入 `笔记信息.md`；不确定的词保留 `【疑似：…】` 或 `【待确认】`，不猜。

校正版定稿后生成时间码字幕（逐字稿名以实际文件为准，常见是 `001-视频`）：

```bash
python3 <本 Skill 目录>/scripts/transcript_srt.py build \
  --timing "暂存目录/转写/原始识别/001-视频.json" \
  --transcript "暂存目录/转写/校正版逐字稿/001-视频.md" \
  --video "暂存目录/视频.mp4"
```

输出 `暂存目录/转写/校正版逐字稿/001-视频.srt`：每条是校正版的一个小句，时间来自原始识别，校正时补的字按前后字的时间插值，`【疑似：…】` 标注跟着所在的句子。校正版里能在原始识别中原样找到的字不到八成时，脚本会停下，这通常说明两份文件不是同一条视频。之后再改校正版逐字稿，要用现有字幕当时间来源重建：`--timing "…/001-视频.srt" --force`。笔记「校正版逐字稿」部分在校正版文件链接下加一行 `- 时间码字幕：[[转写/校正版逐字稿/001-视频.srt]]`。

### 5. 严格验收并正式入库

对暂存目录运行：

```bash
python3 <本 Skill 目录>/scripts/validate_workspace.py "<工作文件夹>" \
  --target "市场调研/对标素材/.staging/目标目录" \
  --strict --json
```

暂存区的严格检查会要求每份校正版逐字稿旁有同名 `.srt`，并检查字幕能解析、时间码递增不重叠、条数合理（按覆盖时长每分钟 6 到 120 条，单条不超过 60 秒）、末条不超出视频时长 1 秒以上、字幕文字和校正版正文逐字一致。验收通过后，把整个暂存目录移动到 `未参考/<平台>/` 下的正式目录。任何一步失败都保留暂存目录和原文件，报告具体失败，不用空文件或视频描述冒充逐字稿。

### 6. 清理中间转写版本并复验

暂存目录严格验收通过并改名到正式目录后：

1. 再次确认校正版文件非空，且全文已经写入 `笔记信息.md`。
2. 把 `转写/` 下除 `校正版逐字稿/`（含 `.md` 和 `.srt`）外的所有文件和目录，按原相对路径移进 `<工作文件夹>/回收站/YYYY-MM-DD_对标素材逐字稿中间版本/<素材目录名>/`；只做可恢复的移动，不永久删除。
3. 删除 `笔记信息.md` 中指向 `validation.json`、原始识别、分段复核、分段源或 manifest 的链接，只保留校正版文件和时间码字幕的链接。
4. 对正式目录重新运行严格检查，并要求字幕：

```bash
python3 <本 Skill 目录>/scripts/validate_workspace.py "<工作文件夹>" \
  --target "市场调研/对标素材/未参考/<平台>/正式目录" \
  --strict --require-srt --json
```

正式目录中残留任何非校正版转写文件、失效链接，或缺少、检查不过的时间码字幕，都算没完成入库。

不得清理 `.staging/` 下的条目或任何还没通过校正版验收的内容。清理失败时停下并保留可恢复的文件，不用删除命令强行收尾。

### 7. 更新检查报告

在 `市场调研/对标素材/_入库检查报告.md` 追加本次结果：日期、正式目录、平台、作品 ID、图片数、视频数、逐字稿状态、时间码字幕（条数、原样对上的比例）、重复检查结果、暂存验收结果、中间版本清理结果和正式目录严格验收结果。只追加，不覆盖旧记录；文件不存在就新建。

## 完成后报告

只报告：正式目录、保存了哪些文件、图片和视频数量、逐字稿是否通过验收、时间码字幕是否生成并通过检查、是否发现重复、还缺哪些真实信息、有哪些 `【疑似：…】` 要用户看。没有正式目录或严格检查没通过时，明确写「尚未完成入库」。

## 失败处理

- 输入信息和媒体对不上：停在暂存区，列出冲突，不猜哪份属于哪条内容。
- 作品 ID 或链接已存在：不新建目录；用户要求补资料时在原目录追加，并重新验收。
- 只有标题相同：不判重复，照常走暂存流程，但在报告里列出标题相同的旧文件夹请用户核对。
- 视频损坏、零字节或短解码失败：不转写、不正式入库，保留原文件位置和检测结果。
- 转写中断或校正版没通过验收：保留全部转写证据和暂存目录，单项重跑；不清理中间版本，不把部分识别结果写成完整逐字稿。
- 生成字幕失败（对上比例不足、时间来源缺失）：停在暂存区，核对原始识别和校正版是不是同一条视频；不手写或估时间码冒充字幕，不清理中间版本。
- 只有原始识别 `.srt`、没有 `.json`：可以用 `.srt` 当 `--timing`，句内字的时间按平均分配估计，报告里说明。
- 只有标题或一张截图，没有正文、链接和可读媒体：可以暂存，但不能算有效对标内容。
