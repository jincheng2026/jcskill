# 入库规范

下面的路径都相对工作文件夹（找法见 SKILL.md「先找到工作文件夹」）。

## 目录与文件

一条作品只建一个目录：

```text
市场调研/对标素材/未参考/<平台>/<平台>_<标题>_<作品ID或链接短哈希>/
├── 笔记信息.md
├── 01.jpg
├── 02.jpg
├── 视频.mp4
└── 转写/
    └── 校正版逐字稿/
        ├── 文件名.md
        └── 文件名.srt
```

没有某类材料时不创建对应空文件或空目录。

`文件名.srt` 是与校正版逐字稿同名的时间码字幕：文字取校正版逐字稿正文，时间取 `jc-zhuanxie` 原始识别，由 `scripts/transcript_srt.py build` 在暂存区生成，不重新转写、不花钱。

原始识别、分段复核、分段源、`manifest.json` 和 `validation.json` 只在 `.staging/` 中用于转写与验收。校正版通过验收并进入正式目录后，把这些中间证据移进 `回收站/YYYY-MM-DD_对标素材逐字稿中间版本/`；正式素材目录不保留。

## `笔记信息.md` 最小结构

```markdown

> 入库日期：YYYY-MM-DD
> 平台：抖音 / 小红书 / 视频号 / 其他真实平台名
> 作品 ID：真实 ID；没有则写「未提供」
> 信息来源：用户复制的作品信息与用户提供的本地媒体

## 基础信息

| 字段 | 内容 |
| --- | --- |
| 作品链接 | 去掉无关追踪和时效参数后的稳定链接 |
| 作者昵称 | 未提供时如实写「未提供」 |
| 发布时间 | 保留原始时区或页面原文 |
| 作品描述 | 完整保存，不拿描述第一句冒充平台标题 |
| 页面数据 | 原样保存记录时间与可见字段 |

## 原始复制内容

【用户粘贴内容原文，一字不改】

## 本地媒体

- 图片：
- 视频：
- SHA-256：
- 媒体检测：

## 本地图片

![[01.jpg]]

## 校正版逐字稿

- 校正版文件：[[转写/校正版逐字稿/文件名.md]]
- 时间码字幕：[[转写/校正版逐字稿/文件名.srt]]

【完整校正版逐字稿】
```

## 去重顺序

1. 同平台、同作品 ID：判定重复。
2. 规范化链接相同：判定重复。规范化只移除 query、fragment、末尾 `/`，不改作品路径。
3. 已记录的媒体 SHA-256 相同：判定重复；即使标题或链接不同也停下核对。
4. 只有标题相同不直接判重，只提示用户人工核对。

## 正式入库完成条件

- `笔记信息.md` 存在、非空，标题、平台和稳定来源可读。
- 原始复制内容完整保留；没有复制文本时，必须有可读本地媒体及其来源说明。
- 图片非零字节并按顺序嵌入笔记。
- 视频通过 `file`、`ffprobe` 和短解码，SHA-256 已记录。
- 有视频时，`.staging/` 中的校正版逐字稿和 `validation.json` 同时存在且验收通过。
- 有视频时，每份校正版逐字稿旁有同名 `.srt`：能解析；时间码递增、相邻两条不重叠；条数合理（覆盖一分钟以上时每分钟 6 到 120 条，单条不超过 60 秒）；末条不超出视频时长 1 秒以上；字幕文字与校正版正文逐字一致（逐字稿改过就要重建字幕）。
- 正式目录的 `转写/` 下只有非空的 `校正版逐字稿/`（校正版 `.md` 和同名 `.srt`），没有原始识别、分段复核、分段源、manifest、validation 或指向它们的失效链接。
- 三层去重没有命中其他正式目录。
- 严格验证脚本退出码为 0；正式目录复验时带 `--require-srt`。
- 以前入库、当时没生成字幕的旧素材，检查整个素材库时不带 `--require-srt`，不报缺字幕；有字幕就按同样标准检查。

## 权限与回滚

- 默认只复制用户提供的本地媒体，不移动原文件。
- 默认不登录平台、不抓取评论、不调用付费接口。
- 所有写入先进入 `.staging/`；严格验收前不进入 `未参考/<平台>/` 下的正式素材目录。
- 失败时不删除暂存区。用户可以修复后重跑，或明确要求后移进 `回收站/YYYY-MM-DD_原文件名`。
- 验收成功后的中间转写证据只移进 `回收站/`，可以按原相对路径恢复。
