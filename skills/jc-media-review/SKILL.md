# 复盘

一条视频发出去满 7 天、数据抓齐以后，给它写复盘。复盘只写一处：这条视频档案 `已发布/YYYY-MM-DD-标题/内容.md` 的「复盘」一节。档案由 jc-publish-closeout 建，数据也是它抓的；本 Skill 只读、只写「复盘」这一节。

要用的脚本是 jc-publish-closeout 的 `stats.py`，和本 Skill 装在同一个地方：`<本 Skill 目录>/../jc-publish-closeout/scripts/stats.py`（下面简写成 `stats.py`）。运行前先确定本 SKILL.md 所在的文件夹，用完整路径调用。找不到这个脚本，说明 jc-publish-closeout 没装，请用户装上（复盘要读它建的档案）。

## 先找到工作文件夹

你的选题、草稿、素材都放在「工作文件夹」里（和创作工作台 jincheng-workbench 用的是同一个）。每次开工先找到它，按顺序找，找到就停：

1. 这个对话打开的文件夹，或者它往上几层，里面有 `内容草稿/` 或 `选题库/00_选题总览.md`。
2. 装了创作工作台：`~/Library/Application Support/jincheng-workbench/config.json` 里的 `workFolder`（`~` 开头的换成家目录）。
3. `~/Documents/jincheng-workbench/` 存在。

都没有：用总入口 `jc` 的建文件夹脚本建好（和本 Skill 装在同一个地方，`<本 Skill 目录>/../jc/scripts/init_workfolder.py`，运行 `python3 <这个路径>`，它只补缺的、不覆盖），告诉用户一句建在哪。找不到 `jc` 时，只在 `~/Documents/jincheng-workbench/` 下建 `已发布/`。

本 Skill 读这几处：`已发布/` 里这条视频的档案和 `00_已发布总览.md`，`选题库/` 里这条的选题卡，`内容草稿/T001_选题名/`（定稿、改稿日志、参考拆解）；工作文件夹里有你自己的会议记录或运营沟通记录时也读。只写这条档案 `内容.md` 的「复盘」一节。

## 这些地方停下等你

| 什么时候 | 你要判断什么 |
| --- | --- |
| 复盘写好了 | 先在聊天里给你看全文。你说「行了」「可以写进去」，AI 才写进档案；你改哪句就改哪句 |
| 「下一篇怎么调」 | AI 最多列 3 个候选，每个写清依据。选哪个、或者一个都不选，由你定，AI 不替你选 |
| 要抓小红书的评论，或者这次花钱超过默认上限 | 同不同意花这笔钱 |
| 数据前后矛盾（比如采集时间早于发布时间） | 以哪个为准。AI 指出来，不擅自改 |
| 7 天数据还没齐 | 等齐了再写，还是先按已有的写 |

## 硬规则（全程有效）

1. **不编**：不补写档案里没有的数据、评论、粉丝来源或平台规则；没有评论就写「暂无评论」，不生成示例评论。不搜外部资料来解释数据。
2. **不改原话**：数据、时间、链接、评论原话照抄。
3. **不向用户要数**：数据只从档案里拿（`内容.md` 的「数据」一节，也就是 `数据.jsonl` 里 12 小时、7 天两次）。某个平台某个时间点没采到，照写「没采到」和原因，不拿别的时间的数顶替。只有视频号这类抓不了的平台、档案里也没有手动记的数时，才可以问一句用户手上有没有截图（有就先用 jc-publish-closeout 记进档案，再来复盘）。
4. **晚采照写**：实际采集时间比到点晚的，照写实际时间和晚了多久，不把晚采的数说成准点的数。
5. **原因必须附对照**。可以写「可能的原因」，但每一条都要带一个对照：
   - 对照只有两种：**同题的参考视频**（写明来自哪张选题卡，或草稿文件夹里的 `参考拆解.md`），或**自己账号的同类视频**（写明来自 `已发布/00_已发布总览.md` 或哪个档案）。
   - **比比例，不比绝对数**：收藏除以点赞、评论除以点赞、转发除以点赞，拿得到播放时再加点赞除以播放。账号体量和发布时间不一样，播放、点赞的绝对数没法比。
   - 原因只说到**选题、开头、表达、制作、分发、转化**六块里的哪一块，不写「某一句导致了什么」；整条数据好，也不说某一句（包括开头）写得好。
   - 每条原因后面接一句「下一条具体改什么」。
   - 找不到对照的，不写原因，放进「还不能判断」，写明还缺哪个对照。
6. **只基于这些材料**：这条档案里的数据、评论原话、逐字稿，对应的选题卡和草稿文件夹，你自己的会议记录（有的话）。
7. **先给看再写入**：没得到用户同意，不改 `内容.md`。

## 流程

### 第 1 步：找到这条视频的档案

- 按 T 编号找：`已发布/` 里 `内容.md`「发布事实」的 T 编号等于这个编号的那个文件夹；没有编号就按标题和发布日期找。用户只说「这条该复盘了」，运行 `python3 stats.py due --workfolder <工作文件夹>`，看「7 天数据齐了、还没复盘」那一行。找不到就告诉用户，不另建文件。
- 读 `内容.md` 全文：发布事实、平台链接、数据、完整逐字稿（以这里的校正版为准，录的时候可能临场改过）。
- 「数据」一节里有平台的 7 天还写着「还没到」或「到点了，还没抓」：告诉用户缺哪个平台哪个时间点，建议先用 jc-publish-closeout 抓齐。用户仍要先写，就按已有的写，缺的照写「还没采到」。
- 「复盘」一节已经有内容：在原复盘上补，不另起一份；写入时旧版会自动备份。

### 第 2 步：收齐材料

- **数据**：按硬规则 3、4，三个平台分开写，12 小时、7 天各一行，带实际采集时间和晚了多久。
- **评论原话**：用 TikHub 抓公开评论：

  ```bash
  python3 stats.py comments <作品链接> --max 50 --save "<档案>/评论_YYYY-MM-DD.json"
  ```

  抖音一条约 0.004 美元，在默认上限内直接跑；小红书要先问用户同意（脚本会停下，退出码 3）。挑出有信息量的几条原样摘进复盘，注明平台和抓取日期。抓不到就写「没抓到」和原因（没有 TikHub 密钥、余额不够、评论区关了），不生成。视频号抓不了，用户有截图就摘截图里的原话，没有就写「视频号评论没抓」。
- **同题的参考视频**：这条的选题卡（`选题库/<类型>/已做/T001_选题名.md`）里的参考视频和它们的数据；草稿文件夹 `内容草稿/T001_选题名/参考拆解.md`。
- **自己账号的同类视频**：`已发布/00_已发布总览.md` 里同一类（看各自选题卡在哪个类型文件夹）、已满 7 天的几条，需要细看就打开它们的档案。
- **改稿过程**（需要时）：`内容草稿/T001_选题名/` 的 `定稿.md`、`改稿日志.md`。
- **会上说过的**（可选）：工作文件夹里有你自己的会议记录或运营沟通记录（比如你告诉过放在哪，或者文件名带「会议」「纪要」「沟通」）时，按 T 编号、标题关键词找到谈到这条视频的地方，把定下的结论摘进来，每条写明谁说的、哪天（有逐字稿时间点也写上）。只摘原话意思，不替他们补结论。没有这类记录就整节不写。

### 第 3 步：写复盘，先给用户看

在聊天里按这个顺序写（小标题用 `####`，写进档案时不会打乱 `内容.md` 的结构）：

```
#### 已确认的事实
（数据、时间、评论里直接能读出来的事；没采到的写没采到和原因）

#### 会上说过的
（有会议记录才写：每条写明谁说的、哪天）

#### 初步观察
（每条写清依据：哪个数字、哪条评论、逐字稿哪个位置）

#### 可能的原因（附对照）
（每条三样：哪一块；对照的比例和出处；下一条具体改什么）

#### 还不能判断
（找不到对照的；写明还缺哪个对照）

#### 下一篇怎么调
（最多 3 个候选，每个写清直接依据；用户选定的那一项；没选写「用户还没选」）
```

「下一篇怎么调」**不替用户选**。用户把候选全否了是正常结果，照实写「都没采用」。

有一条规矩要守：**评论区里的提问不直接拿来当下一条的选题**。先去找市面上已经有数据的同类视频，再看它们的评论区，确认这个需求不止出现在自己这一条下面。

### 第 4 步：用户说行了，再写入

1. 把用户确认后的全文存成一个临时 Markdown 文件（放系统临时文件夹）。
2. 运行：

   ```bash
   python3 stats.py review --archive <档案> --file <临时文件>
   ```

   它先把旧的 `内容.md` 备份到档案的 `.history/`，再把复盘写进「复盘」一节（开头注明复盘日期和「用户看过」），并在 `已发布/00_已发布总览.md` 这一行标「已复盘」。
3. 告诉用户写进去了，给档案链接。
4. 提醒一句：要把复盘里的结论变成下次写稿的规矩，用 jc-skill-writer 的「照复盘改 Skill」，多数结论会先写进 `写稿方法/07_我的判断库.md`，改判断库也要用户同意。

## 固定应答

用户说「这篇数据很低，没什么可复盘的」或类似的话时，回：

> 单篇数据不足是正常的，价值在多篇对比，积累 3 到 5 条再看趋势。

然后照常把真实记录做完，不跳过。

## 出问题时

- 找不到档案：告诉用户，请他先用 jc-publish-closeout 建档；不在别处另建复盘文件。
- 选题卡、参考拆解不存在：对照只能用自己账号的同类视频；也没有的，原因全部写进「还不能判断」，告诉用户还缺什么。
- 自己账号满 7 天的同类视频还不到 3 条：照写，并说明对比的条数少，结论更要谨慎。
- 数据互相矛盾：指出来请用户确认，不擅自修正。
- `review` 报错找不到档案或读不了文件：照它的话处理，不手改 `内容.md` 绕过去。

## 和别的 Skill 的分工

- 建档、认作品、抓 12 小时和 7 天的数：jc-publish-closeout。
- 写下一条：jc-jiaocheng-video。找新的对标、看别人的评论区：jc-media-research。
- 把复盘结论落进判断库或写稿 Skill：jc-skill-writer。
