# jc-gongzuotai-write：创作页

第一版逐字稿出来以后，AI 把它放进「创作页」：你在网页上直接改字、写批注、对 AI 的修改建议点「采纳」或「不采纳」，改动停笔 1 秒自动存回文件；AI 用命令读回你的改动、回复、提新建议，直到你认稿。

创作页的网页模板、生成脚本和保存服务都在开源的「创作工作台」仓库里（https://github.com/jincheng2026/jincheng-workbench 的 `creation-page/`）。本 Skill 不复制一份脚本，而是用你电脑上装好的工作台，这样页面和脚本永远是同一个版本。具体每一步的命令和填法，照工作台自带的写稿 Skill（仓库里的 `skills/jincheng-workbench-write/SKILL.md`）对应的几节做，本 Skill 只写清楚：什么时候用、先做什么、照哪几节、和本系列别的 Skill 怎么接、哪里停下等你。

## 这些地方停下等你

| 这一步 | 你要判断什么 | AI 在这之前不做什么 |
| --- | --- | --- |
| 生成创作页之前 | 叙事你同意过、第一版逐字稿已经有了 | 叙事没定就不生成页面（在聊天里定，用 jc-jiaocheng-video） |
| 每条修改建议 | 采纳还是不采纳 | 不把 AI 的改法直接写进「我的版本」 |
| AI 要整段换新稿 | 你在聊天里明确说「换」 | 不在你没点头时改你的稿 |
| 内容确认 | 你勾选页面上的「内容已确认」或在聊天里说定了 | 不提前出标题、封面文字、简介，不推进阶段 |
| 标题、封面文字、简介 | 选哪个 | 不替你定 |
| 定稿后整理判断 | 每条判断你逐条回「同意」才记进判断库 | 不把 AI 觉得有道理的写法直接写进你的判断库 |

## 第 0 步：确认工作台装好、找到东西

1. 找工作台代码文件夹 `WB`，按顺序，找到就停：`~/jincheng-workbench` 里有 `creation-page/where.py`；工作台正在运行时 `pgrep -f 'scripts/start.mjs' | while read p; do lsof -a -p "$p" -d cwd -Fn | sed -n 's/^n//p'; done` 打印的文件夹；`mdfind -name where.py | grep '/creation-page/where.py$'` 往上两层。
2. 都找不到，就是还没装：先用一句话告诉用户「创作页要用开源的创作工作台，我先把它装好，大概要几分钟，中间可能请你点几次允许」，然后照 https://github.com/jincheng2026/jincheng-workbench 仓库里的 `docs/给AI的安装说明.md` 装好（它会检查 Node、pnpm、Python，缺什么装什么，装好会在浏览器打开工作台，并把工作台的三个 Skill 装进 Codex 和 Claude Code）。装好再接着做。
3. 每条命令开头都重新写一遍 `WB="…"`（每次调用终端都是新的，变量留不下来）。然后运行：

```bash
WB="$HOME/jincheng-workbench"   # 换成上面找到的
python3 "$WB/creation-page/where.py" T001
```

它会打印工作文件夹、内容草稿、写稿方法在哪，保存服务在不在，这条内容的草稿文件夹和创作页在哪。后面的路径都以它的输出为准。本系列别的 Skill（jc-jiaocheng-video 写的 `工作稿.md`、jc-video-analysis 写的 `参考拆解.md`）用的是同一个工作文件夹，这里能直接读到。

如果 `where.py` 打印的工作文件夹，和你之前用本系列 Skill 时建的工作文件夹不是同一个（比如本系列先建在别处，工作台又建了一个新的），停下，把两个路径都告诉用户，问用哪一个；用户选了以后，按工作台仓库 `docs/配置说明.md` 改工作台设置里的 `workFolder`，不自己挪文件。

## 照工作台写稿 Skill 做的几节

打开 `"$WB/skills/jincheng-workbench-write/SKILL.md"`，按下面对应关系做（节名以那个文件里的为准）：

| 你说的 / 现在的情况 | 照那个文件的哪几节 |
| --- | --- |
| 每次开工 | 「先找到东西在哪」「先看能不能写工作文件夹」，再读「名词」「规矩」两节 |
| 第一版逐字稿写好了，要做成创作页 | 「三、生成创作页」第 1 到 5 步 |
| 「改完了」「看一下」「页面上写了几句给你」「建议我定完了」 | 「四、和你配合的循环」第 1 到 6 步 |
| 勾了「内容已确认」，或者「出标题」「标题封面简介」「标题我定了」 | 「四」里的「第 7 步：标题、封面文字、简介」 |
| 写稿结束 | 「什么时候算完，以及越做越好」（定稿后整理判断，逐条等你同意） |
| 页面打不开、存不上、冲突框、建议原句对不上、生成校验不通过 | 「五、出问题怎么办」对应的那一种 |
| 已经有创作页又要重新生成、类型换了等 | 「六、边界情况」 |
| 每次生成后 | 「验收（每次生成都要过）」，再看「禁令」 |

那个文件里的「加选题」「一、开工：读写稿方法」「二、从选题到第一版逐字稿」三节，在本系列里由 jc-jiaocheng-video 负责（它有叙事确认、教程和口播两种写法、画面规划、发布前评审），本 Skill 不重复做。用户在这里直接说「帮我写 T001」而这条还没有第一版逐字稿时，转到 jc-jiaocheng-video。

## 和本系列别的 Skill 怎么接

- **稿子从哪来**：jc-jiaocheng-video 叙事确认后写的 `内容草稿/T001_选题名/工作稿.md`。生成页面时，「我的版本」每段的原文用程序从 `工作稿.md` 切出来，不重打。
- **参考原话从哪来**：jc-video-analysis 写的 `参考拆解.md` 和 `参考素材/` 里的校正版逐字稿；对标素材用 jc-benchmark-intake 入库过的，在工作文件夹 `市场调研/对标素材/` 里，带同名时间码字幕 `.srt`，「看原片」从某一段开头播靠它。参考原话一字不改，引号里的话先用程序在逐字稿里搜到才能打引号。
- **改稿日志**：jc-jiaocheng-video 在草稿文件夹里记 `改稿日志.md`。创作页上的采纳、不采纳和你亲手改的字，定稿时 AI 从读回摘要里补一节进改稿日志（「段号｜原句 → 新句｜谁改｜为什么」，用户没说原因的标「AI 归纳」）。
- **标题、封面文字、简介**：按上面第 7 步出候选。简介要写成发布配文时，可以照 jc-jianjie 的写法出；出标题前读工作文件夹 `已发布/00_已发布总览.md` 最近 10 行，看同类视频哪种标题数据好（没有这个文件就跳过）。封面图本身用创作工作台的封面 Skill（jincheng-workbench-cover），这里只出封面上的字。
- **定稿以后**：提词稿从页面取（页面上「复制提词稿」）。要剪辑用 jc-koubo-shuping；发布后用 jc-publish-closeout 建档。
- **判断库**：定稿后整理出来、你同意的判断，写进工作文件夹 `写稿方法/07_我的判断库.md`。jc-jiaocheng-video 下次写稿会读它。

## 不做的事

- 不在叙事没定、第一版逐字稿没写完时生成页面。
- 不用编辑工具直接改创作页的 HTML，只用工作台的 `build_page.py` 和 `brain_page.py`。
- 不为某一条内容改工作台的页面模板和脚本；发现脚本的问题，告诉用户可以去工作台仓库提 issue。
- 不凭聊天记忆说「你改了什么」，以读回摘要为准。
